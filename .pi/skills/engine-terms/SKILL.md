# 引擎概念用词

规则不在本技能里。唯一所有者是 `docs/terminology.md` 的「四个实体」「机制词」「已废弃的说法」「新概念怎么定词」四节——动手前先读，不要凭记忆复述。

本技能只补三件所有者写不出来的事：动手的次序、可机械检查的那部分、验证命令的来源。

## 开工前

1. 先判断这段文本指的是哪个概念；概念本身含糊就先定概念，再定词，不要顺手挑一个近义词。
2. 全仓搜同义词，代码注释、提示词、seed、测试断言一起搜：`git grep -n "场景"` 这类命令比通读快。
3. 一个词必须同批改完：运行期文案、记忆与观察的标题、工具描述、测试断言、文档与索引。断言晚一批，测试必红。
4. 数据可重灌：改了提示词或内容就 `db:reset --yes` 再 `db:seed`，不写兼容层，也不迁历史局。

## 收尾自检

跑一次随附脚本：`node .pi/skills/engine-terms/scripts/check-terms.mjs`。

它只判机械部分：框架层（`apps/server/src`、`apps/server/scripts`、`seeds/global-rules.ts`、`docs/`、根 `README.md`）出现废弃说法即列出；`docs/terminology.md` 自身豁免，因为它是词表的定义处。确实要保留原词时，在同一行写 `terms-allow: <词>` 并说明理由。

它是手动检查，不接进 `pnpm lint`、不阻断提交：发现即报告给用户，由人决定改不改，不自行扩大改动范围。

脚本报不出来的两类，自己过一遍：

- 内容层的散文（seed 正文、知识库）不按词表判，但一旦指代实体就必须用正名；`场景` 这类词只能用于叙事，不能指地点实体。
- 语义分层不是同义词：`动作`/`行动`、`轮次`/`回合`、`观察`/`观测` 各指不同的东西，别按近义合并。

## 验证

改动落在提示词或内容上时，除了词表检查还要跑 `pnpm lint` 与 `pnpm -C apps/server test:run`；命令来自根 `package.json` 与服务端 `package.json`，不手抄参数。
