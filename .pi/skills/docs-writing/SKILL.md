# 引擎文档写作

规则不在本技能里。唯一所有者是 `docs/README.md` 的「归属」「写作约束（AI 编写文档时必须遵守）」「何时新建文档」三节——动手前先读它们，不要凭记忆复述。

本技能只补三件所有者写不出来的事：动手的次序、可机械检查的那部分、以及验证命令的来源。

## 开工前

1. 先判断归属层：引擎与系统才进 `docs/`；使用、启动与工具链去根 `README.md`；内容与验收去 seed 目录的随附 md。跨层文档只写它与其他系统的关系。
2. 找「被它取代的那段话」：用关键词 `grep -rn` 扫 `docs/`，连代码注释里的 `docs/…` 一起搜。默认动作是删，不是加。
3. 新概念优先并入现有文档；确实要新建时，同一轮里更新索引表。

## 收尾自检

跑一次随附脚本：`node .pi/skills/docs-writing/scripts/check-docs.mjs`。

它只查可机械判定的部分，判不了的留给「写作约束」：索引是否覆盖全部文档、链接是否都指向存在的文件、有没有围栏代码块、`→ 参见：` 的写法是否成立、索引表是否按列宽对齐（中文按两列宽算）。

脚本报不出来的两类，自己过一遍：

- 同篇内部指引写成「见「某小节」」，不要套 `→ 参见：[…](…)`——那是跨文档格式。
- 每段跑两个问句：产物一改这句会不会写错（会就删）；删掉这段意图是否仍完整（完整就删）。

## 验证

`pnpm lint:md`，命令与排除规则来自根 `package.json`，不手抄参数。
