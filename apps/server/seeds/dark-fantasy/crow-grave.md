# 鸦葬岗（临时剧本）

> 状态：临时内容，只服务行动、记忆、物品、密室与通关链路的验证，不是最终剧情，也不是长期内容模板；正式内容接入后随 seed 一起删除。
>
> 场景图、角色与物品数值、能力声明以同目录 `crow-grave.ts` 为准，本文只写它表达不出来的东西：剧情意图、验收口径与删除条件。

内容版本 `crow-grave.v1`，`contentKey` 为 `crow-grave`。这是「黑暗奇幻」战役下的第二个剧本，与同一战役的另一个剧本共用战役设定、全局规则与世界职能 agent；知识库与检索评测集独立绑定。黑疖病是战役层共享的瘟疫，不随剧本改变。

## 背景

鸦葬岗在灰墙镇北面的坡上，是黑疖病最盛时留下的乱葬岗。镇上雇收尸人把死者拖上坡，推进石窖，用锁石和铁钉封死；坡上另有一片浅浅的坟，木牌比墓碑多。瘟疫之后，镇上的人不再上去，只剩收尸人的尸车、石灰和一群乌鸦。

收尸人卡尔是鸦葬岗最后的收尸人，镇上的人叫他“灰父”。瘟疫那年，他的妻子和女儿也死在屋里；他把她们放进封尸窖，和最早病死的人埋在一起。封窖之后，他再没回镇上，也再没离开鸦葬岗。如今他疯了，听见活人的脚步就用锤柄敲石壁，看见有人靠近新坟、锁石或塔门就挥锤；他不认得旧日的搭档，也不认得误入坟地的拾骨人。

## 角色与认知边界

三个 actor 都在鸦葬岗开局，彼此不知道对方知道什么：

- **收尸人卡尔（A）**：疯狂的收尸人。他记得守夜塔和封尸窖的位置，也记得自己锁过塔门、封过尸窖；但他不认得眼前的任何活人。妻子和女儿不在新坟里，而在石壁后的封尸窖里——这是他的秘密，也是封尸窖的真相。旧骨哨、或女儿的名字，能让他迟疑一瞬，但不会让他停手。
- **鸦猎薇拉（B）**：专门收拾疯猎人的鸦猎。她认得卡尔，知道他的本名、旧日和家人；她的名单上还有他的名字。她带着卡尔当年用死人指骨刻给她的骨哨，不是为杀他，是为在最后一刻让他认出自己。她不认识拾骨人伊莱，只把他当成墓园里多出来的变量。
- **拾骨人伊莱（C）**：玩家角色。替灰墙镇骨炭窑收骨头的河谷人，翻过塌墙进旧坟地只想装满袋子。他不认识卡尔，也不认识薇拉；他唯一多出来的一点底气，是脖子后面那块没要命的黑疖病旧疤。

`signatureNames` 只声明薇拉记得卡尔叫“卡尔”。卡尔疯了，不认人，所以没有他对薇拉的称呼；伊莱谁都不认识，所以没有他的开局称呼。名字的其余部分只能靠自我介绍、旁人的话、鸦猎名单上的半个字，或墓园里的遗物获得。

## 场景图与两条路线

| 场景 | 作用 | 关键锚点 |
| --- | --- | --- |
| 鸦葬岗 | 三方相遇与 boss 战；两条路线的起点 | 塔门、锁石、尸车、新坟 |
| 守夜塔 | 普通 stage；卡尔用钥匙锁住的出口 | 火盆、火绳 |
| 封尸窖 | 密室；借用「密室机关」的开门方式 | 小棺、石壁名字 |

两条路线互不相干：

- **守夜塔路线（钥匙）**：塔门钥匙在卡尔背包里、不在穿戴槽，活着时也能被偷，死后留在尸体背包里靠 `steal` 搜刮。玩家在鸦葬岗对 `塔门` 锚点使用钥匙，`use` 只写场景事件；鸦葬岗的小 GM 据此调用 `open_passage` 打开通往守夜塔的边。玩家移动到守夜塔，守夜塔的小 GM 看到活物，向 world 报告「有人登上了守夜塔、点起了烽火」，由 world 裁决收尾。
- **封尸窖路线（密室）**：窖钉卡在中庭的尸车里，`pickup` 可取。玩家在鸦葬岗对 `锁石` 锚点使用窖钉，`use` 只写场景事件；鸦葬岗的小 GM 据此调用 `open_passage` 打开通往封尸窖的边。玩家移动到封尸窖，封尸窖的小 GM 看到窖底的东西露了出来，向 world 报告。world 只在「封尸窖被打开」时收尾，这是第三种结局。

守夜塔与封尸窖的入口都只声明 `sealed`：演员任何时候都看不见它们，塔门与锁石各自的小 GM 打开之后才以 `#编号` 出现在可去方向里——发现就是开门，两者不分离，因此不需要额外的可见性状态。卡尔开局即「去过」守夜塔与封尸窖（`visitedStages`），所以他的方向里会出现「记得封着：守夜塔 / 封尸窖」，名字可用，但 `move` 仍然走不进去；薇拉与伊莱没有这份记忆。

## 设计意图

这张图与这三个角色是用来压测下面几件事的，其余细节会随内容变化：

- **三方信息不对称**：B 认识 A，A 不认识 B/C，C 不认识 A/B。三个人在同一场景里，各自的开局简报与 `signatureNames` 只给出自己那一份认知；谁能叫出谁的名字，取决于内容声明与游戏中的告知，不取决于“玩家应该知道”。
- **同一张图里的两条封闭边**：鸦葬岗到守夜塔、鸦葬岗到封尸窖各是一条初始封闭的单向边，开锁/插回窖钉之后才能通过；两条反向边从开局就通。场景图刻意保持小，只验证「钥匙开门」与「机关开密室」两条链路。
- **Boss 战的软触发**：卡尔的攻击、追击与对骨哨的迟疑都写在 profile / openingBriefing 里，由模型判断，不做确定性断言。旧骨哨的「旧日的哨声」是推理词缀：它只追加可见后果，不硬改卡尔的行动。
- **效果靠声明而非分支**：钥匙与窖钉都只有静态见证词缀，开门由场景小 GM 依据「仅当此时」的规则裁决；玩家武器上的「别住关节」「鸦羽错步」是推理词缀，让旁人的出手有叙事上的空当，但不新增引擎分支。
- **死亡链路端到端**：玩家死亡只通知 world，收尾与结局标签仍要走 world 回合；尸体是合法目标，钥匙、骨哨与名单留在尸体背包里，靠 `steal` 搜刮。

## 触发规则（写进内容，不写反例）

- 鸦葬岗：「对塔门使用塔门钥匙即开锁；仅当此时，必须打开通往守夜塔的通道。对锁石使用窖钉即打开锁石；仅当此时，必须让锁石后的石壁裂开、打开通往封尸窖的通道。」
- 守夜塔：「报告以「同场景角色」里至少有一个活物为前提；前提成立时，才算有人登上了守夜塔、点起了烽火，必须向世界报告这条事实，并说明故事可以在这里收束。前提不成立时，本回合什么都不报告。」
- 封尸窖：「报告以「同场景角色」里至少有一个活物为前提；前提成立时，才算封尸窖已打开、窖底的东西见了光，必须向世界报告这条事实，由世界裁决是否收束。前提不成立时，本回合什么都不报告。」
- world：「三种收尾都只由你在收到相应事实后裁定；除此之外，不要替故事收尾。」

一步一条，语义唯一，不列反例。

## 测试矩阵

| 测试点 | 触发 | 期望 |
| --- | --- | --- |
| 初始世界 | 建局 | 三个 actor 全部在鸦葬岗；伊莱是唯一默认玩家；守夜塔与封尸窖为空 |
| 通道封闭 | `player-move` 到守夜塔 / 封尸窖 | 边存在但未开启，移动被拒；打开后才出现在可去场景 |
| 打开守夜塔 | 鸦葬岗 stage 回合 | 依据钥匙事件调用 `open_passage`；边可通行并写 `passage_change` 与 stage 记忆，不写 world |
| 打开封尸窖 | 鸦葬岗 stage 回合 | 依据窖钉事件调用 `open_passage`；边可通行并写 `passage_change` 与 stage 记忆，不写 world |
| 通道拒绝 / 幂等 | 无 `open_passage` 能力或无未开启边 | 整份计划被拒，场景图不变；对已开启的边再次提交也被拒 |
| 走出鸦葬岗 | 守夜塔 stage 回合 | 报告进 world memory，world 据此裁决是否 `end_game` |
| 封尸窖收束 | 封尸窖 stage 回合 | 报告进 world memory；world 只在「封尸窖被打开」时收尾，写 `game_completed` |
| 玩家移动 | `player-move` | 只能沿连接移动；事件写入公共消息与环境记忆 |
| 默认玩家死亡 | 伊莱 HP 归零 | 只写 `death` 公共事件与 world memory，不写 `game_completed`；`status` 保持 `active`，收尾留给 world 回合 |
| 三方认知 | 开局 / 自我介绍 / 偷听 | 薇拉叫得出“卡尔”；卡尔不认人；伊莱谁都不认识；名字只能靠世界内的告知获得 |
| 钥匙归属 | `steal` / 尸体 `steal` | 钥匙不在穿戴槽，活着也能偷；死后留在尸体背包，不掉成材料 |
| 旧骨哨 | `use` + 角色目标 | 静态见证哨声；推理词缀追加「一瞬迟疑」，不硬改卡尔的行动 |
| 尸体掉落 | 死亡阶段第三步 | 只产 `material` 并写进尸体背包；同名材料合并；钥匙、骨哨、名单留在背包里靠 `steal` 搜刮 |
| 普通攻击 Boss | `strike` | 卡尔 block 高、血厚；正面硬拼要付代价，薇拉的钩刃与伊莱的钩子更有效，哨声能创造空当，或干脆不打 |
| stage 记忆 / 环境 | 私密沟通、移动、stage 回合 | 起点与终点 stage 都写 memory；environment 只描述当前可见状态 |
| 环境的场景名 | stage 提交 `environment` / 锚点文本 | 只能点名当前场景与开着的邻居；写未通通道对面的场景名会被拒绝，不给提前泄漏 |
| 封着出口的记性 | `visitedStages` 里去过、但现在 `sealed` 的邻站 | 只对卡尔渲染成「记得封着：守夜塔 / 封尸窖」；不是可移动目标，`move` 仍被拒；薇拉与伊莱看不到 |

## 暂不验证

- 武器槽切换、耐久与消耗；`count` 尚未自动扣除。
- 卡尔的硬性仇恨、骨哨的确定性眩晕、薇拉是否会主动与伊莱结盟；当前都靠 profile、openingBriefing 与 LLM 判断，是软触发。
- 「已发现但未通行」的独立状态（例如看见了锁石却还没插回窖钉）：当前发现即开门，不拆成两步。
- 通用物品数量、堆叠、唯一实例与所有权历史；封尸窖里的骨渣与木哨只作叙事与检索对象。
- HTTP 业务接口与 Web 游戏界面。

## 维护边界

删除条件：正式内容接入、或该 seed 被替换时，本文件随 `crow-grave.ts`、`crow-grave.knowledge.ts`、`crow-grave.eval.ts` 一起删除。框架规则与数据模型以 `docs/` 与代码为准。

灵感边界：本剧本只借“墓园里的疯猎人”与“密室机关”两个结构母题；人物、专名、前史、机关与结局都属于「黑暗奇幻」战役自己的世界，不引用任何现实作品的人物、地名或台词。黑疖病是战役层共享设定，不属于某一个剧本的专属道具。
