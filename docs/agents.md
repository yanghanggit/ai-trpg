# Agent 与工具

分类只回答两个问题：是否吃世界宪法、是否记得上一轮；题材与触发方式会变，这两件事不会。吃宪法的是世界面——用词、可见后果与术语都要落在世界里；只服务框架自身的是框架面。

## 世界面内三类

再按「有没有实体身份与累积上下文」分三类。

- **记忆实体**：拥有独立 memory 的实体 agent，即 `MEMORY_OWNER_TYPES` 登记的那几类。身份、设定与长期状态都由自己的 memory 承载，system prompt 是宪法；一局内可以有很多个，按实体逐个推进，事务、快照与 compact 都以 owner 为单位。
- **旁路**：不新建实体，只借某个记忆实体的一份记忆做一次推理，因此不重复携带设定。产物写回目标实体的是外观，属运行流程；只回给调用方的是只读型探针——它让内容自己开口，不是搬运内容，也就不进框架工具那一类。
- **世界职能**：世界级单例，和 world 平级，但没有 memory。有自己的**宪法**，分三段——**职责**（产出什么）、**世界宪法**（战役设定与全局规则）、**本职能**（内容给的口径：这件事在这个世界里怎么判、写到什么尺度、哪些专名要保住，后接该 agent 不可协商的约束）。宪法在内容层定档、是**开局快照**：改代码或内容都不影响进行中的局，也不随部署收紧。输入由调用方现场组装（可跨多个实体、事件流或物品），产出是世界面文本、判定，或对某个记忆实体 memory 的改写。每种职能只有一份实现，与 `MEMORY_OWNER_TYPES` 的多份实例相反。掉落、词缀、故事整理、记忆压缩与玩家对话审核都在此列。

记忆实体与世界职能的唯一判据是**有没有累积记忆**；两者都吃宪法，区别只在那份上下文是否跨轮累积。世界职能的文本属内容（战役级，一个 agent 一处），机制属代码：工具、参数与类别枚举不下放，否则内容能改写判定程序。平台级禁令也随文本走——它属于该 agent 的约束，由框架的校验保证没被漏掉。

被否：按题材分成角色 / 场景 / 世界（回答不了「新的 LLM 调用该不该带 memory」）；把旁路并进世界职能（丢掉「为什么能沿用目标宪法」）；把世界职能并进记忆实体（让记忆实体失去唯一判据）。

## 框架工具

世界面之外，既不持记忆也不吃设定——**换一份 seeds 不需要改它一行**：审查（框架文本审查、名字审计）、观测搬运（轨迹与导出）与验证（冒烟、评测）。

判据问它自己的口径，不是输入：**可以读内容、搬运内容、检查内容，但不能被内容定义**。名字审计读含世界内容的记忆，规则却与题材无关——注入设定反而会把合法用法判成泄漏。它与世界职能的差别只有一条：吃设定就失去「框架是否依赖题材」这个探测手段。

被否的命名：「引擎工具」与游戏引擎进程混淆，「内部工具」「自检工具」按使用者或职能命名，都回答不了「新的 LLM 调用该不该带设定」。

文生图暂按「要不要题材风格」划：需要材质、时代与审美的归世界职能，纯技术参数的归框架工具；生成做深之后按同一判据复核。

## Prompt 分层

- **system prompt** 是**宪法与索引**，由三段构成：**宪法**（身份、战役设定、全局规则、不可协商的约束）、**内容**（外部传入的设定，如人设与本职能口径）、**职责**（核心任务概述，不写工具细节；只有世界职能有这一段）。记忆实体把它写进长期 memory、不参与 compact；世界职能的是一份开局快照。两者都只写稳定且必须永远成立的内容。
- **任务提示词**（每轮 input）给本轮可见事实、当前状态与目标，以及工具之间的调度顺序。
- **工具描述**只写这个动作自身的契约：参数、效果与边界；不引用其它工具，也不承担流程或长期规则。

判断标准：换一个工具就失效的写进工具描述；只对本轮或动作顺序有效写进任务提示词；与具体动作无关、整局都要成立的写进 system prompt。

## 设定注入

`campaignSetting` 是每局的世界宪法。世界面内的 agent 都要拿到它：否则材质名与压缩后的术语会退回模型的世界外常识，而下游看不出题材越界。

设定是约束，不是剧情事实。记忆实体与世界职能都经各自的 system prompt 携带（世界职能的宪法另加它自己的一份口径）；旁路直接沿用目标的宪法。任务提示词只放本轮事实——内容不进任务层，这一条比「让模型别当真」的劝告更可靠。框架工具是唯一不注入的一组：注入反而让判定被内容带偏。
