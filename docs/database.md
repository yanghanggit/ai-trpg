# 数据库

PostgreSQL 是游戏状态的唯一真相：回合从库里读状态与 memory、在短事务里落账，进程重启不改变游戏状态；CLI 与 HTTP 复用同一服务层，没有第二份权威世界对象。

## 聚合与归属

表按聚合归属，读侧不跨聚合拼装权威对象。细节各自归口，这里只记存储形状的意图。

- **对局**：`games` 是聚合根，承载状态、world 自己命名的结局、内容版本与并发版本；座位与玩家接管是它的附属，接管不改 actor 本体。
- **世界**：一局一个 `worlds`；`stages` 与 `stage_connections` 组成舞台图，边是有向的，运行时只能把已有出边从封闭打开。锚点与道具都挂在舞台上，锚点是道具的作用域；锚点由内容层给初值，运行时可由声明了该能力的 stage 调整。
- **角色**：`actors` 依附舞台；可变生命值与恒定属性分开存，`hp` 归零就是死亡，没有死亡状态列，收尾是归零之后的派生流程、与行动事务解耦；形态与外观各有自己的记录，穿戴是 actor 上的槽位索引；actor 本身不存视觉字段。
- **名字**：签名称呼按「观察者 × 签名」记录，再次写入覆盖；换签名即失去旧称呼。它只存观察者当前的叫法，不做名字抽取。
- **事件与记忆**：公共事件流只追加、带可见性与游标，供拉取与审计；私有记忆按 actor / stage / world 分开，压缩只重写自己的记忆。两者不合并：`mind` 只进记忆。
- **向量**：只装世界知识，`access` 列承载阅读门槛，collection 与模型分开隔离；不承载私有记忆或剧情秘密。

## 读取分层

按用途分三档，能取小的不取大的：确认存在只读 id 与版本；回合、判定与渲染读活状态切片，不含事件流；只有快照、故事整理与导出读整局。事件流随对局线性增长，所以回合结果只交切片加游标，调用方按游标增量拉取。派生索引不跨请求缓存，随状态快照一起回收。

→ 参见：[架构与契约](architecture.md)

## 写入边界

LLM 调用不进事务；工具 handler 只暂存计划；落账前整份计划重新校验，任何一条失败整份丢弃；同一局的写入靠行锁与版本号串行化。扣血必须原子：写生命值接收身份而不是快照，在带行锁的读里取当前值再写——静态命中与词缀追加会连续结算同一目标，拿旧快照写会互相覆盖。

「玩法模块不写 SQL」的边界由架构与源码扫描守住，这里不重复清单。

→ 参见：[架构与契约](architecture.md)

## 开发期形状

建局是唯一一次把内容包物化成行的时机；之后 PostgreSQL 是唯一真相，改内容不会回改已有游戏。开发期不搬运旧数据：形状变化直接重建 baseline，再用当前内容重置重刷；迁移只描述目标形状，不维护增量历史。重置清单是新增业务表的登记点，重置与演示数据只允许本机数据库。
