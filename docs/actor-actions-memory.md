# Actor 行动与记忆

## 结论

actor 是唯一行动主体。NPC 与玩家不是两种实体，而是同一个 actor 的两种控制者；接管只改变谁提交行动，不改变身份、场景归属、物品、状态或 memory，释放后继续使用原 memory。两路只在行动如何产生上不同，校验与落账共用同一套规则；工具只暂存计划，玩家入口跳过计划与工具。

→ 参见：[数据库](database.md)、[Agent 与工具](agents.md)

## 行动事实

actor 长期 memory 是下一次 LLM request 的稳定上下文；`game_messages` 是公共事件流，过程轨迹不是下一轮 prompt。三者不能互相替代。

每次成功动作只留一条行动事实：做了什么、结果；台词动作保留说出口的原文。行动结果后附落账后的场景、在场称谓与陈列物品，失败与拒绝也带这份状态；它取最终状态，移动后不会写成起点。计划里的内心独白与玩家入口的 `reason` 只进过程轨迹，不写长期 memory。词缀的追加后果另走自己的通道，不在动作事实里重复。

长期 memory 只由引擎写入：system prompt、可选的 `openingBriefing`，之后是行动事实、观察与认知更新。任务提示词与工具轨迹不进入长期 memory。

→ 参见：[数据库](database.md)、[词缀](affixes.md)

## 过程轨迹

一次 loop 的完整消息按回合进过程轨迹，不进长期 memory。轨迹不是状态，不能决定角色知道什么，也没有主动回读入口。

→ 参见：[开发期 Agent 工作流](debug-workflow.md)

## 名字与记忆

memory 按 actor 隔离。名字是认知而不是地址：观察者可以叫真名、称号、误认或听来的叫法；真名没有特权。引用如何拼、场景名何时可知，归术语表与信息披露；这里只保留记忆侧的两条边界：记名字只改自己的认知，不产生公共事件，也不占行动；名字按签名存，换签名后旧称呼不跟过去，切回来才恢复。

路线回忆（`recall_route`）走同一条认知通道：结论只写进自己的记忆，不产生公共事件，也不占行动。这段文字只给模型读，不是客户端展示文案，所以按模型好读来组织——标题一行、路径一行，多条并排；能规划到哪、走不通时怎么说，归信息披露。

场景知识的授予也留一条认知，把 `#序号` 与名字绑起来：先前的路线可能已经把同一个地方记成编号，没有这条绑定，记忆里就会出现两个彼此无关的标签。

引擎不做名字抽取；新名字只能来自内容层的开局声明或角色自己的回合。玩家接管的台词在写库前还要过审核。

→ 参见：[术语表](glossary.md)、[信息披露](information-disclosure.md)、[名字审计](name-audit.md)、[玩家对话审核](dialogue-audit.md)

## 记忆生命周期

`openingBriefing` 是内容层给单个 actor 的本局私有简报，建局时注入一次并进入长期 memory；没有简报就没有这条消息。memory 压缩把历史压成叙事摘要，system prompt 不动，旧消息归档成可递归展开的树；只能显式触发。摘要保留关键事件、关系、最近一次明确的场景状态与未解决冲突，不保留工具调用与一次性环境描写，也不是固定的行动日志。actor 的摘要落账前过名字审计，不通过则旧 memory 不变。

→ 参见：[Seed 内容编写原则](seed-authoring.md)、[数据库](database.md)、[名字审计](name-audit.md)

## 信息不对称

沟通按听见范围分公开、私密与跨场景定向；`call` 不携带来源身份，发起者的结果也不写目标所在场景。移动与传送都是瞬时跨场景事实：当事人知道从哪到哪，旧场景只看到他离开，新场景只看到他进入，路线组合不写给旁观者。战斗的完整数值只进公共事件与场景记忆；受害者自己的观察才带剩余 HP，其他观察者只知道伤害与是否倒下。

→ 参见：[传送](teleport.md)、[信息披露](information-disclosure.md)
