# 临时测试剧本：枯钟修道院

> 状态：临时内容，只服务当前行动、记忆、物品与通关链路的验证，不是最终剧情，也不是长期内容模板。

剧本定义在 `apps/server/seeds/dark-fantasy/bell-monastery.ts`（战役文本在同目录的 `campaign.ts`），内容版本为 `dark-fantasy.v13`，剧本标识（`contentKey`）为 `bell-monastery`，由 `createGame` 物化为具体游戏状态。测试世界使用独立的小型 `TEST_WORLD`，不随本剧本变化。

## 背景（暗线）

一场被称作“黑疖病”的瘟疫扫过河谷：先死牲口，再死人，腋下与脖颈鼓起黑硬的疖子。枯钟修道院收留过病人，也烧过尸体；等院长发现唱诗班一个接一个倒下时，他下令封死北面的铁闸门，带着还能走的修士从别的路离开。钟楼从那以后再没响过。

留下的只有掘墓人奥德里克、他的狗，以及地窖里的鼠群。老鼠在尸堆与酒桶之间繁殖，鼠王靠吃尸体活了下来——它身上的跳蚤、它啃过的粮食、它钻过的裹尸布，都是这场瘟疫的一部分。玩家扮演的无名者被封进一口刻满符文的棺材，架在乱葬坑的坑沿醒来——瘟疫死者从不用棺材下葬。

| 连接端点 | 方向 | 说明 |
| --- | --- | --- |
| `场景.棺材` / `场景.墓园` | 棺材 → 墓园 | 单向出口；离开后无法返回 |
| `场景.墓园` / `场景.地窖` | 双向 | 石阶向下通地窖；坏运气报信与鼠王移动都经过墓园 |
| `场景.墓园` / `场景.焚尸房` | 双向 | 小屋后的焚尸房 |
| `场景.墓园` / `场景.铁闸门` | 双向 | 墓园北侧岩壁；铁闸门不经过焚尸房 |
| `场景.铁闸门` / `场景.山道` | 铁闸门 → 山道（初始封闭） | 只能由铁闸门的小 GM 打开；没有反向边，走出去就回不来 |

焚尸房与铁闸门是墓园下的平级叶子节点，两者之间没有连接；墓园没有通往棺材的边，所以棺材只能出不能进；地窖只能原路返回墓园；山道只有一条被封闭的入边，打开前不可达、到达后无路可去。从初始的棺材到山道只有一条路径：棺材 → 墓园 → 铁闸门 →（开门）→ 山道。

`角色.无名者` 是默认玩家角色（`isDefaultPlayer: true`），死亡时整局结束。`角色.奥德里克` 持有 `饰品.闸门钥匙`；`角色.坏运气` 是鼠王唯一不攻击的子嗣；`角色.鼠王` 的 openingBriefing 声明自己正在地窖沉睡：本场景出现任何说话、攻击或非等待行为（包括坏运气进窖报信）即苏醒，苏醒后追杀本场景所有非鼠类活物，没有目标时自行搜索修道院；HP 120、damage 60、block 100。焚尸房的 `武器.松脂火把` 是 `damage 8`、`block 0` 的武器，词缀为“火焰顺着毛根渗进去：对多毛类生物额外造成武器伤害的一百倍，毛越厚烧得越透”；名字、描述与词缀都不提“鼠”，命中与否由 affix agent 依据目标的种族与外观判断。`角色.鼠王` 与 `角色.坏运气` 的外观带“厚毛皮 / 蓬松的灰毛”，`角色.煤渣` 的外观是“短毛”，所以普通角色无法靠基础伤害击穿鼠王，而火把的词缀会在 LLM 结算中放大对它的伤害。

### 角色能力（种子中逐条显式声明）

能力写在每个 actor 的 `actions` 里，没有共享默认值；场景能力同样逐条声明：所有场景都必须声明 `submit_environment`（内容校验强制），只有铁闸门额外声明 `open_passage`，只有山道额外声明 `notify_world`——走出修道院之后才向 world 报告。world 的 `actions` 声明 `notify_stage` 与 `end_game`。

| 角色 | 是否活物 | 移动/说话类 | 战斗 | 道具操作（give/pickup/use） | steal |
| --- | --- | --- | --- | --- | --- |
| `角色.奥德里克` | 是 | say/whisper/announce/move/wait | attack | ✅ | ❌ |
| `角色.煤渣` | 动物 | say/whisper/announce/move/wait | attack | ❌ | ❌ |
| `角色.坏运气` | 动物 | say/whisper/announce/move/wait | ❌ | ❌ | ❌ |
| `角色.无名者` | 是 | say/whisper/announce/move/wait | attack | ✅ | ✅ |
| `角色.鼠王` | 动物 | say/whisper/announce/move/wait | attack | ❌ | ❌ |

动物不操作道具，因此煤渣、坏运气、鼠王都不会 `give` / `pickup` / `use` / `steal`；煤渣与鼠王会 `attack`，坏运气不会。鼠王沉睡期间只用 `wait`、苏醒后追杀一切非鼠类活物（唯独不伤坏运气），这两条都写在 openingBriefing 里，由 LLM 执行；系统没有苏醒状态，也没有跨场景信息广播。

### 动物语言

语言边界只写在动物自己的 `profile` 里，不写进 `SYSTEM_RULES`，由 LLM 在角色设定内执行：

- 煤渣是不说人话的犬；对非同族只会低吼、呜咽、磨牙或短促的“汪汪”，只有遇到同族犬时才用清晰语言交流；
- 坏运气对非同族只会“吱吱、丝丝”、磨牙或尖叫；与鼠王同属鼠类时可以用清晰语言；
- 鼠王对非同族只会发出鼠叫，绝不说人话；对坏运气等鼠类同族可以清楚说话；
- 三个动物都可以在心里正常思考，`mind` 不受叫声限制。

## 剧情路径

谈判路线：玩家推开棺盖、沿土坡爬进墓园，与奥德里克沟通。铁闸门的钟形纹下刻着一句旧铭文：“灰烬之下，旧钟无名”；有人对他说出这句话，他会把对方当成留下守钟的故人，并在下一轮使用 `give` 交出钥匙。玩家走到铁闸门、对锁孔使用钥匙：`use` 只写场景事件，由铁闸门的小 GM 调用 `open_passage` 打开通往山道的通道；玩家再移动到山道，山道的小 GM 向 world 报告“有人逃出了修道院”，由 world 裁决是否结束。

暴力路线：玩家攻击奥德里克，煤渣通过同场景战斗记忆在下一次 NPC 回合自主反击；坏运气看到冲突后跑回地窖报信。鼠王是否苏醒由 openingBriefing 与 LLM 判断，不通过系统状态移除。玩家可以趁奥德里克活着时窃取他背包里的钥匙（活着时拿不走已穿戴的物品，他死后则什么都能拿）。

Boss 路线：鼠王被本场景的非 `wait` 行为惊醒后，按 openingBriefing 追杀所有非鼠类活物；没有目标时由 LLM 根据场景图自行决定搜索方向。当前攻击力足以秒杀普通角色。普通攻击无法伤害鼠王；火武器需要先装备到 `weapon` 槽，`attack` 才会用它结算。

## 测试矩阵

| 测试点 | 触发 | 期望 |
| --- | --- | --- |
| 初始世界 | `agent:game create --seed dark-fantasy` | 六段场景、墓园三 actor、棺材一 actor、地窖一 actor、焚尸房为空且有场景物品、铁闸门与山道为空；玩家出生在棺材 |
| 通道封闭 | `player-move` 到 `场景.山道` | 边虽存在但未开启，移动被拒绝；只有打开后才出现在可去场景里 |
| 打开通道 | 铁闸门 stage 回合 | 小 GM 依据钥匙使用事件调用 `open_passage`；边变为可通行，写 `passage_change` 公共事件与 stage 记忆，不写 world memory |
| 通道拒绝 | 无 `open_passage` 能力的场景，或没有未开启边 | 整份计划被拒绝，写入 stage 记忆，场景图不变 |
| 通道幂等 | 对已开启的边再次 `open_passage` | 没有未开启边，工具不暴露；直接提交也会被拒 |
| 逃出后报告 | 山道 stage 回合 | 只有山道有 `notify_world`；报告进入 world memory，world 回合据此裁决是否 `end_game` |
| 玩家移动 | `player-move` | 只能沿连接移动；移动事件写入公共消息与环境记忆 |
| 感知 | NPC 的 `observe_actor` | 只能查看同场景角色携带的物品；不返回 stats 或状态 |
| 攻击 | `player-attack` 或 NPC `attack` | 伤害为 `max(0, damage - block)`；目标生命下降；死亡 actor 不再进入 loop，但仍可被攻击（伤害空转） |
| 默认玩家死亡 | 伤害使 `isDefaultPlayer` actor 的 HP 归零 | 写 `game_completed`，`games.status=completed`，后续行动被拒绝 |
| 动物语言 | NPC `say` / `whisper` / `announce` | 同族可清晰沟通；对非同族只能发出本族叫声；`mind` 不受限制 |
| 狗的反应 | 攻击奥德里克后推进煤渣 | 煤渣通过战斗记忆、profile 与 openingBriefing 自行决定攻击凶手；不是硬触发器 |
| 坏运气报信 | 冲突后推进坏运气 | 坏运气移动到地窖，下一轮可对鼠王说话；是否需要两轮由计划顺序与两条上限决定 |
| 沉睡唤醒 | 场景内发生对话、攻击或非 `wait` 行为 | 由鼠王 openingBriefing 与 LLM 判断是否苏醒；系统没有状态移除规则，也不做确定性断言 |
| 窃取 | `steal` | 物品从目标转到发起者；事件为 private；只有发起者与目标有记忆；目标存活时下一轮会反应；活人只能拿背包，尸体上的东西都能拿 |
| 给予 | NPC `give` 或暗语触发 | 物品从发起者转到同场景存活目标；暗语通过 say 写入记忆，奥德里克下一轮自行选择 give；没有硬控制状态 |
| 拾取 | `pickup` | 场景物品移入 actor 背包；场景物品消失 |
| 使用钥匙 | `use` | 对当前场景使用钥匙，并传入 `targetDetail`（如“锁孔”）；只写场景事件，不改变连通性、不通知 world；开门由铁闸门 stage 的下一轮裁决 |
| 游戏结束 | ① world 执行 `end_game`（如钥匙开门）；② 默认玩家角色死亡 | ① world 主动结束；② 默认玩家角色死亡由系统置 `games.status = completed`；两者都写 `game_completed`，后续行动被拒绝 |
| 普通攻击 Boss | `attack` | 鼠王 block 100，空手伤害为 0；火把 damage 8，对鼠类词缀由 LLM 额外放大一百倍伤害 |
| 鼠王攻击 | 苏醒后推进鼠王 | damage 60，普通角色会被秒杀；清空本场景后由 LLM 自行搜索下一个场景 |
| stage 记忆 | 私密沟通或 actor 移动 | 起点与终点 stage 都写入 memory；私密事件只对 stage 与既有可见者可见 |
| stage 环境仲裁 | `stage --stage <name>` | stage 读取本场景事件并更新 environment；写 `environment_change` 事件与 stage memory |
| 环境约束 | 提交包含角色名的 environment | 环境更新被拒绝，stage 写入拒绝记忆，场景不变 |
| 场景物品同步 | 拾取场景物品后推动 stage | environment 只描述当前物品与当前可见状态；不写物品消失、被拿走或历史痕迹；拾取事件保留在 stage memory |
| stage 后 actor | 推动 stage 后再推进 actor | actor 下一次 plan 的当前环境包含新的 environment；不写 actor observation |
| actor 探针 | `probe --actor` | 只依据 actor memory 回答；不注入当前 observation、不写 memory、不产生事件、不改变版本 |
| stage 探针 | `probe --stage` | 只依据 stage memory 回答；不注入当前 environment 或场景物品、不改变 environment |

## 已用真实 provider 验证

- 玩家推开棺盖爬进墓园后，奥德里克按 profile 先盘问来路，不直接动手。
- 玩家移动到墓园、攻击奥德里克后，煤渣下轮自主攻击玩家。
- 坏运气在冲突后移动到地窖并报信；鼠王是否苏醒由 openingBriefing 与 LLM 判断。
- 鼠王苏醒后会自行搜索并秒杀遇到的非鼠类活物；从未攻击坏运气。
- 玩家可私密窃取钥匙，目标获得被窃取记忆，旁观者没有该记忆。
- 玩家对奥德里克说出暗语“灰烬之下，旧钟无名”后，奥德里克下一轮先回应，再 `give` 交出钥匙。
- 玩家可拾取焚尸房场景物品。
- 玩家拾取 `武器.松脂火把`、装备到 `weapon` 槽后攻击鼠王；默认 fixed damage 为 0，随后 affix LLM 依据鼠王“厚毛皮”的外观判定命中，补充“基础 damage × 100”的伤害并击杀（实测 800）。
- v13 实测（奥德里克由玩家接管）：对锁孔使用钥匙后，铁闸门 stage 一轮内完成 `open_passage + submit_environment`，未通知 world；走到山道后，山道 stage 一轮内完成 `notify_world + submit_environment`；world 一轮内 `notify_stage ×2 + end_game` 收束，`status=completed`。
- 同一局走到山道后，山道 stage 自行调用 `notify_world`，报告“封锁被打破、有人逃出”；world 收到报告后自行裁决；把上限调到 3 之后，`notify_stage ×2 + end_game` 可以在同一轮完成，实测该局以 `game_completed` 收束。
- 玩家推动奥德里克、再推动墓园、再推动奥德里克：墓园 environment 已更新，奥德里克的下一次 plan 读取到新环境，stage memory 同时保留本场景事件。
- 玩家在焚尸房拾取 `武器.松脂火把` 后推动焚尸房：stage 依据当前场景物品（已为空）与 pickup 记忆，生成只描述当前焚尸房状态的 environment，不再出现火把，也不写消失过程或历史痕迹。
- 对焚尸房发起 stage 探针，依据 stage memory 回答当前场景没有火把；对无名者发起 actor 探针，依据 actor memory 回答自己曾拾取火把；两次探针都不写入 memory 或游戏事件。

## 暂不验证

- 武器槽、装备切换、耐久与消耗；当前武器通过 `damage` effect 参与 `attack`，`count` 尚未自动扣除。
- 场景物品拾取后的数量堆叠与其他武器效果。
- 暗语的硬性服从规则；当前只靠 profile 与 LLM 判断，暗语是软触发，不是状态机。
- 沉睡/苏醒的确定性行为；当前同样只靠 openingBriefing 与 LLM 判断。
- HTTP 业务接口与 Web 游戏界面。
- 通用物品数量、堆叠、唯一实例与所有权历史。
