# 临时测试剧本：灰烬墓园

> 状态：临时内容，只服务当前行动、记忆、物品与通关链路的验证，不是最终剧情，也不是长期内容模板。

剧本定义在 `apps/server/seeds/dark-fantasy.ts`，内容版本为 `dark-fantasy.v5`，由 `createGame` 物化为具体游戏状态。测试世界使用独立的小型 `TEST_WORLD`，不随本剧本变化。

## 测试意图

用一个五段式小剧本同时覆盖：

- 多场景、双向与单向连接、非对称信息；
- 玩家接管、移动、谈判、攻击、窃取、拾取与使用道具；
- NPC 的事件记忆驱动反应，而不是系统硬触发；
- 私密事件与公开事件的 memory 差异；
- 沉睡的 LLM 行为与致命 Boss；
- stage 小 GM 的场景记忆与环境仲裁；
- 钥匙通关与游戏结束状态；
- 为火武器、场景物品和最终内容预留扩展点。

它不追求完整战役，也不把临时规则固化成正式玩法。

## 场景图

| 场景 | 角色 | 场景物品 | 用途 |
| --- | --- | --- | --- |
| `场景.守墓人的灰庭` | `角色.守墓人`、`角色.守墓犬`、`角色.灰尾小鼠` | 无 | 钥匙、谈判、暴力、狗与报信小鼠 |
| `场景.浅眠墓穴` | `角色.苏醒者` | 无 | 玩家控制的主角起点 |
| `场景.鼠王的骨厅` | `角色.鼠王` | 无 | 沉睡 Boss、鼠王幼崽、致命威胁 |
| `场景.焚毛炉房` | 无 | `武器.焚鼠火把` | 火武器伤害 |
| `场景.封骨之门` | 无 | 无 | 钥匙通关终点 |

连接由三组双向边和一条单向出口组成，全部以灰庭为枢纽。双向表示两个方向各有一条有向边；单向表示只有一个方向存在边：

| 连接端点 | 方向 | 说明 |
| --- | --- | --- |
| `场景.浅眠墓穴` / `场景.守墓人的灰庭` | 浅眠墓穴 → 灰庭 | 单向出口；玩家离开浅眠墓穴后无法返回 |
| `场景.守墓人的灰庭` / `场景.鼠王的骨厅` | 双向 | 鼠洞；小鼠报信与鼠王移动都经过灰庭 |
| `场景.守墓人的灰庭` / `场景.焚毛炉房` | 双向 | 小屋后的灰烬小径 |
| `场景.守墓人的灰庭` / `场景.封骨之门` | 双向 | 灰庭北侧岩壁；封骨之门不经过焚毛炉房 |

各场景当前可前往的邻居：

| 场景 | 可前往 |
| --- | --- |
| `场景.守墓人的灰庭` | `场景.鼠王的骨厅`、`场景.焚毛炉房`、`场景.封骨之门` |
| `场景.浅眠墓穴` | `场景.守墓人的灰庭` |
| `场景.鼠王的骨厅` | `场景.守墓人的灰庭` |
| `场景.焚毛炉房` | `场景.守墓人的灰庭` |
| `场景.封骨之门` | `场景.守墓人的灰庭` |

焚毛炉房与封骨之门是灰庭下的平级叶子节点，两者之间没有连接；浅眠墓穴只能单向离开，灰庭不能返回墓穴；鼠王的骨厅只能原路返回灰庭。从初始的浅眠墓穴到封骨之门只有一条路径：浅眠墓穴 → 守墓人的灰庭 → 封骨之门。

### 角色能力（种子中逐条显式声明）

能力写在每个 actor 的 `actions` 里，没有共享默认值；场景的 `actions` 目前全部为空（不额外限制）。

| 角色 | 是否活物 | 移动/说话类 | 战斗 | 道具操作（give/pickup/use） | steal |
| --- | --- | --- | --- | --- | --- |
| `角色.守墓人` | 是 | say/whisper/announce/move/wait | attack | ✅ | ❌ |
| `角色.守墓犬` | 动物 | say/whisper/announce/move/wait | attack | ❌ | ❌ |
| `角色.灰尾小鼠` | 动物 | say/whisper/announce/move/wait | ❌ | ❌ | ❌ |
| `角色.苏醒者` | 是 | say/whisper/announce/move/wait | attack | ✅ | ✅ |
| `角色.鼠王` | 动物 | say/whisper/announce/move/wait | attack | ❌ | ❌ |

动物不操作道具，因此狗、老鼠、鼠王都不会 `give` / `pickup` / `use` / `steal`；狗与鼠王会 `attack`，幼崽不会。鼠王沉睡期间只用 `wait` 是 profile 约束（LLM 判断），不是能力缺失。

`角色.守墓人` 持有 `饰品.封骨钥匙`；`角色.灰尾小鼠` 是鼠王唯一不攻击的子嗣；`角色.鼠王` 的 profile 声明自己正在沉睡，只有听见对话、被攻击或场景发生非 `wait` 行为后才苏醒；HP 120、attack 60、defense 100。焚毛炉房的 `武器.焚鼠火把` 是 `damage 250`、`block 0` 的武器；玩家 attack 6 加上武器后可以一击打穿鼠王。

## 剧情路径

谈判路线：玩家进入灰庭，与守墓人沟通。守墓人有一个不主动说出的暗语：“灰烬之下，旧钟无名”；有人对他说出这句话，他会把对方当成故人，并在下一轮使用 `give` 交出钥匙。玩家沿场景图到达封骨之门，使用钥匙通关。

暴力路线：玩家攻击守墓人，守墓犬通过同场景战斗记忆在下一次 NPC 回合自主反击；小鼠看到冲突后移动到骨厅报信。鼠王是否苏醒由 profile 与 LLM 判断，不通过系统状态移除。玩家可以窃取守墓人的钥匙，包括从尸体上取走。

Boss 路线：鼠王被非 `wait` 行为惊醒后会自行移动和攻击；当前攻击力足以秒杀普通角色。普通攻击无法伤害鼠王；火武器可通过 `attack` 的 `itemNames` 参与本次攻击。

## 测试矩阵

| 测试点 | 触发 | 期望 |
| --- | --- | --- |
| 初始世界 | `agent:game create` | 五段场景、灰庭三 actor、墓穴一 actor、骨厅一 actor、焚毛炉房为空且有场景物品、封骨之门为空；旁白落在浅眠墓穴 |
| 玩家移动 | `player-move` | 只能沿连接移动；移动事件写入公共消息与环境记忆 |
| 感知 | NPC 的 `get_actor` | 只能查看同场景角色；返回 stats 与目标背包 |
| 攻击 | `player-attack` 或 NPC `attack` | 伤害为 `max(0, attack - defense)`；目标生命下降；死亡 actor 不再进入 loop |
| 狗的反应 | 攻击守墓人后推进狗 | 狗通过战斗记忆与 profile 自行决定攻击凶手；不是硬触发器 |
| 小鼠报信 | 冲突后推进小鼠 | 小鼠移动到骨厅，下一轮可对鼠王说话；是否需要两轮由计划顺序与两条上限决定 |
| 沉睡唤醒 | 场景内发生对话、攻击或非 `wait` 行为 | 由鼠王 profile 与 LLM 判断是否苏醒；系统没有状态移除规则，也不做确定性断言 |
| 窃取 | `steal` | 物品从目标转到发起者；事件为 private；只有发起者与目标有记忆；目标存活时下一轮会反应；允许对尸体使用 |
| 给予 | NPC `give` 或暗语触发 | 物品从发起者转到同场景存活目标；暗语通过 say 写入记忆，守墓人下一轮自行选择 give；没有硬控制状态 |
| 拾取 | `pickup` | 场景物品移入 actor 背包；场景物品消失 |
| 使用钥匙 | `use` | 目标必须是当前场景、自己或同场景角色；当前硬编码 `场景.封骨之门` 与 `饰品.封骨钥匙` 通关 |
| 游戏结束 | 成功使用钥匙 | `games.status` 变为 `completed`；写 `game_completed` 公共事件；后续行动被拒绝；完成日志写 stderr，避免污染 CLI JSON |
| 普通攻击 Boss | `attack` | 鼠王 defense 100，空手伤害为 0；装备火把后 damage 250，配合 attack 6 足以一击击杀 |
| 鼠王攻击 | 苏醒后推进鼠王 | attack 60，普通角色会被秒杀；鼠王会跨场景移动 |
| stage 记忆 | 私密沟通或 actor 移动 | 起点与终点 stage 都写入 memory；私密事件只对 stage 与既有可见者可见 |
| stage 环境仲裁 | `stage --stage <name>` | stage 读取本场景事件并更新 environment；写 `environment_change` 事件与 stage memory |
| 环境约束 | 提交包含角色名的 environment | 环境更新被拒绝，stage 写入拒绝记忆，场景不变 |
| 场景物品同步 | 拾取场景物品后推动 stage | environment 只描述当前物品与当前可见状态；不写物品消失、被拿走或历史痕迹；拾取事件保留在 stage memory |
| stage 后 actor | 推动 stage 后再推进 actor | actor 下一次 plan 的当前环境包含新的 environment；不写 actor observation |
| actor 探针 | `probe --actor` | 只依据 actor memory 回答；不注入当前 observation、不写 memory、不产生事件、不改变版本 |
| stage 探针 | `probe --stage` | 只依据 stage memory 回答；不注入当前 environment 或场景物品、不改变 environment |

## 已用真实 provider 验证

- 玩家移动到灰庭、攻击守墓人后，守墓犬下轮自主攻击玩家。
- 灰尾小鼠在冲突后移动到骨厅并报信；鼠王是否苏醒由 profile 与 LLM 判断。
- 在状态引擎版本中曾跑通鼠王苏醒、移动到灰庭并秒杀玩家；当前版本改为 LLM 行为，不再做确定性状态断言。
- 玩家可私密窃取钥匙，目标获得被窃取记忆，旁观者没有该记忆。
- 玩家对守墓人说出暗语“灰烬之下，旧钟无名”后，守墓人下一轮先回应，再 `give` 交出钥匙。
- 玩家可拾取焚毛炉房场景物品。
- 玩家拾取 `武器.焚鼠火把` 后攻击鼠王，造成 156 点伤害并击杀。
- 玩家可走到封骨之门，用钥匙使游戏进入 `completed`。
- 玩家推动守墓人、再推动灰庭、再推动守墓人：灰庭 environment 已更新，守墓人的下一次 plan 读取到新环境，stage memory 同时保留本场景事件。
- 玩家在焚毛炉房拾取 `武器.焚鼠火把` 后推动焚毛炉房：stage 依据当前场景物品（已为空）与 pickup 记忆，生成只描述当前炉房状态的 environment，不再出现火把，也不写消失过程或历史痕迹。
- 对焚毛炉房发起 stage 探针，依据 stage memory 回答当前场景没有火把；对苏醒者发起 actor 探针，依据 actor memory 回答自己曾拾取火把；两次探针都不写入 memory 或游戏事件。

## 暂不验证

- 武器槽、装备切换、耐久与消耗；当前武器只通过 `itemNames` 参与本次攻击。
- 场景物品拾取后的数量堆叠与其他武器效果。
- 钥匙条件从内容数据读取；当前是 `actions/use.ts` 中的硬编码常量。
- 暗语的硬性服从规则；当前只靠 profile 与 LLM 判断，暗语是软触发，不是状态机。
- 沉睡/苏醒的确定性行为；当前同样只靠 profile 与 LLM 判断。
- HTTP 业务接口与 Web 游戏界面。
- 通用物品数量、堆叠、唯一实例与所有权历史。
