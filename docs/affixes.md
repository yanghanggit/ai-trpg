# 词缀

词缀是挂在物品上的规则，按触发场景分组：同一件物品可以分别声明挥击（`strike`）、横扫（`cleave`）与使用（`use`）时的后果，未声明的触发不可用。物品只是宿主，词缀不感知自己挂在哪里；每个触发只服务提供对应动作的那把武器。

→ 参见：[物品](items.md)

## 两种结算

词缀分静态与推理两类：

- **静态**：由引擎纯计算，必须无条件、可复现；用于数值与固定见证。
- **推理**：由推理端按规则文本判定，条件写在文本里；能做什么由工具集决定，不由类型枚举。

一个动作先结算静态并提交，再让推理端追加。推理端只做增量：失败只等于这次没有追加，不回滚静态结果，也不阻断后续阶段。静态的实际结果——本次扣掉多少生命、目标是否因此归零——随请求交给推理端，让它不必从反馈文案反推。两类词缀共用同一套见证结构，差别只在由谁生产。

## 伤害与命中

静态伤害先求和，再由动作统一减一次目标防御；公式属于结算实现，不在文档重复。挥击与横扫恒有一次命中（0 也写，横扫逐目标各一次），使用只有声明了伤害才出命中，钥匙这类物品只产生见证。命中只扣生命，是否死亡由死亡阶段按生命派生。

推理端不重复静态已经结算的伤害；追加值由它自己按事实判定。

## 见证

见证是结构化事实：来源、目标与文本模板分离，模板只引用角色、锚点与物品的占位，不含名字。引擎按收件人渲染四份：公共事件流、场景记忆、场景内角色的观察、发起者的行动反馈。名字与指代由引擎决定，推理端无法把真名写进别人的记忆。

发起者不写 observation，同一事实在记忆里只有一条。不可见后果可以只写给目标；目标已死仍写见证，只跳过数值。判定不成立但过程可见时，允许留一条见证；完全不可见就什么都不做。

## 约束

- 静态不允许条件；条件只能写推理词缀。
- 推理端只追加，不改写静态结果，不写他人私有信息。
- 单次执行的见证条数有上限，避免一次词缀淹没记忆。
