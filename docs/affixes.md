# 词缀

词缀是挂在宿主上的自然语言规则。当前唯一的宿主是物品，所以它通常和物品一起出现；宿主与词缀共同构成推理端的输入上下文，词缀本身不需要知道自己挂在哪里。

→ 参见：[架构与契约](architecture.md)

## 两段结算

宿主的声明式效果先由计算端结算并提交，词缀再由推理端判定后追加。推理端只做增量：失败只等于这次没有追加，不回滚已提交的结果。两段的边界与失败语义只有一处定义。

→ 参见：[架构与契约](architecture.md)

## 表达能力来自工具，不来自类型

词缀仍然只是一段文本，效果的种类不预先枚举。推理端能做什么，取决于任务提示词与工具：

- 数值后果走伤害工具，进入计算端已经建立的伤害通道；
- 看得见的后果走记录工具，写进场景的长期记忆。

这样火、酸、冻、寄生这类效果不需要各自的字段或专用工具，换一种词缀就换一种写法；提示词负责约束“只写这条词缀造成的、感官可及的变化”，工具负责形状与上限。

曾经考虑过把后果做成独立的状态类型或角色字段，被否决了：那等于把效果种类编码进 schema，推理端只能输出预定义类型，泛化能力会被重新收窄。

## 叙事去向

可见后果只以第三人称写进场景记忆；actor 记忆不由推理端写入，目标与旁人都要等下一次 pull（目前是 stage 更新 environment 之后）才可能知道。这是有意的延迟：推理端与 actor 之间没有直接通道。

场景记忆是上帝视角，可以带名字；如果将来要让目标“亲身感到”词缀后果，只能加 pull 机制（例如 actor 回合读取待处理事件），不能由仲裁 agent 直接写 actor 记忆。

→ 参见：[Actor 记忆](actor-actions-memory.md)、[外观](appearance.md)

## 约束

- 仲裁 agent 不是实体：读控制面、写世界面。
- 词缀只追加，不改变宿主的声明式效果，也不直接改生命或物品；
- 单次执行能记录几条后果由上限约束，避免一次词缀淹没其它记忆；
- 记录的是可见或可感的后果，不写数值、机制与心理；
- 目标已经倒下时，后果仍要记录——尸体照样会变。

→ 参见：[物品](items.md)、[信息披露](information-disclosure.md)
