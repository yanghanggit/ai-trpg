# 名字审计

actor 记忆的名字边界需要可检查，但不能靠写入路径“顺手纠正”。名字审计因此是一个只读系统：它比对真名与观察者的签名称呼，报告越界与结构缺口，不修改记忆、不改写台词、不阻断回合。

## 判据

真名属于 actor，签名称呼属于观察者；两者来源不同。审计先按观察者收集它给各个签名起过的名字，再把 actor 记忆里出现的其他真名视为候选越界。

自己名字永远合法；对某个主体，只有观察者当前（或 `ever` 范围内的历史）名字绑定正好等于该主体的真名时，这个真名才合法。观察者叫他“守墓人”时，记忆里出现“奥德里克”仍然算越界；反过来，观察者把他记作“奥德里克”，这个名字就合法。

历史名字与当前名字是两个问题：前者回答“是否曾经用这个真名称呼过他”，后者回答“换签名 / 改名后现在是否仍用这个真名”。审计保留两种口径，因为伪装与变身场景需要后者，而普通记忆检查需要前者避免误伤历史。

当前表只存一个当前名字；同一签名被改名后，旧名字不会自动进入 `ever`。若以后需要“旧称呼永远合法”，再单独做名字历史。

compact 摘要也会在落账前走这套白名单：摘要里出现观察者未用过的其他 actor 真名时，压缩被拒绝，旧 memory 不被覆盖。

## 台词

只有 `say`、`whisper`、`announce` 会产生台词；其他事件没有“台词”这一部分。沟通观察把事件类型与说出口的原文作为结构信息一并写入记忆，审计据此区分“台词内的名字”与“叙述里的名字”，而不是从整段文本里猜哪一句是引语。

结构信息缺失时，审计只发结构告警：它不根据正文反推台词，也不补齐字段。名字检查系统的职责是发现，不是纠错。

## 严重度

严重度按写入者分层：引擎写入的观察与反馈本应已经按观察者渲染；模型写入的推理与摘要属于另一层；system prompt 与开场简报属于内容层，可能是刻意设定，也可能需要补名字绑定。分层是为了让报告指向正确的所有者，而不是让审计替所有者做决定。

## 边界

- stage 与 world 自己的记忆是上帝视角，允许写名字，不在扫描范围。
- 角色真名可能与常用词、地点名或物品名重合；这类命中需要结合上下文判断，审计不自动豁免。
- 名字按签名保留，不合并成 actor 级历史；旧签名上的名字仍在，`ever` 口径会把它算作曾经用过。
- 允许任意名字意味着模型可以把真名直接设成称呼；审计只能检查“引擎有没有使用观察者没用过的真名”，不能证明角色真的知道真名。
- 审计只读：它不改变回合结果，也不把发现写回 actor 记忆。
