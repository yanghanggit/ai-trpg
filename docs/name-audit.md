# 名字审计

actor 记忆的名字边界需要可检查，但不能靠写入路径“顺手纠正”。名字审计因此是一个只读系统：它比对真名与观察者的识别关系，报告越界与结构缺口，不修改记忆、不改写台词、不阻断回合。

## 判据

真名属于 actor，识别属于观察者；两者来源不同。审计先按观察者收集它认得的形象，再把 actor 记忆里出现的其他真名视为候选越界。自己名字永远合法；对某个主体，只有识别关系落在该主体的形象上，这个真名才合法。

历史知晓与当前识别是两个问题：前者回答“是否曾经认得这个 actor”，后者回答“换形象后是否还认得”。审计保留两种口径，因为伪装与变身场景需要后者，而普通记忆检查需要前者避免误伤历史。

## 台词

只有 `say`、`whisper`、`announce` 会产生台词；其他事件没有“台词”这一部分。沟通观察把事件类型与说出口的原文作为结构信息一并写入记忆，审计据此区分“台词内的名字”与“叙述里的名字”，而不是从整段文本里猜哪一句是引语。

结构信息缺失时，审计只发结构告警：它不根据正文反推台词，也不补齐字段。名字检查系统的职责是发现，不是纠错。

## 严重度

严重度按写入者分层：引擎写入的观察与反馈本应已经按观察者渲染；模型写入的推理与摘要属于另一层；system prompt 与开场简报属于内容层，可能是刻意设定，也可能需要补识别关系。分层是为了让报告指向正确的所有者，而不是让审计替所有者做决定。

## 边界

- stage 与 world 自己的记忆是上帝视角，允许写名字，不在扫描范围。
- 角色真名可能与常用词、地点名或物品名重合；这类命中需要结合上下文判断，审计不自动豁免。
- 识别按形象保留，不合并成 actor 级历史；旧形象的关系仍在，`ever` 口径会把它算作曾经认得。
- 审计只读：它不改变回合结果，也不把发现写回 actor 记忆。
