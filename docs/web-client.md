# 客户端页面与 mock 目录

## 判据：页面只吃数据

一个页面拆成两层，判据是「谁触网」：**容器**取数、映射、跳转；**展现层**只接收数据，不发请求、不读路由。

这条缝的收益不是好看，而是可替换：同一份页面数据有两个生产者——正式容器与 `mock` 的 fixture。两者都满足同一个类型，谁写错字段都在编译期暴露。页面自己直接取数，mock 就只能去拦网络，组装那天没有 diff 可看。

页面数据的类型来自生成契约（`components["schemas"]["ActorView"]`），不是另立的页面类型：fixture 与真响应满足同一个类型，多一个字段、少一个字段、可空性写错都在编译期暴露。没有中间映射层——`state` 那套上帝视角客户端根本不读，也就不存在「把内部投影翻译成页面数据」这一步。

命名分两条轴，别混用：**目录按路由命名空间**（`pages/game/` = `/g/:slug` 之下所有界面），**组件按它显示的核心**（`StagePage` = 此刻这一个舞台）。所以 `GameRoute` / `GameContainer` 跟 URL 走，展现层跟数据走：一页只吃一份投影，名字就该是那份投影的重心。这样将来加 `ConfigPage`、`ReplayPage` 时，目录里不会有一个万能 `GamePage` 把「这一局」和「其中一屏」混成一个名字。

跨页面的稳定物只有一份：**页面清单**（`key`、正式路径、路由壳）。正式路由与 mock 目录共读它，所以加页面时两边一起出现；清单外的第二份路由表必然漂移。

## 数据怎么到页面

取数在容器里（见上），而「什么时候重新取」也是这份数据契约的一部分，不是页面自己的事。

一局里「正在发生什么」只放在一个地方：作业行。客户端读它有两种读法——按间隔读快照，或订阅变化、由服务器推过来。两种读法读的是同一行、同一个形状，所以换实现不动页面，也不存在「推送版」与「轮询版」两套判断。

订阅只是加速器，不是正确性的前提：连接会断、通知会丢、进程会重启。客户端手里那个「上次看到的位置」才是连续的凭据——重连从它之后补，补不到就整份重读。页面因此不能把「连着流」当成前置条件。

推过来的是那一刻的完整快照，不是变更流水：同一件事在极短时间里改了几次，可能只收到一条。拿它数回合、推中间步骤都会错——步骤看进度，结果只认终态。

重载页面不问「我刚才发了什么」：先问这一局有没有正在跑的作业，有就接上，没有就重读投影。入队成功不代表回合发生过，这个判断只有作业终态能给。

## 能力对照：先有接口，再有界面

判据是「开发期 CLI 能做的，web 必须能做」：两者是同一个契约的两个客户端，前者先跑通，后者才有界面。某个能力只缺界面、不缺接口，是 web 的欠账；连接口都没有，是服务端的缺口——不拿「界面上用不到」当不做的理由。

页面也不另立判断口径。回合算不算数、要不要补空回合、取消有没有生效，都读契约里已有的那几样：作业终态与错误码、顺位的计数与执行方、世界版本。这几样一旦在页面里被重新解释一遍，同一局在 CLI 与 web 上就能走出不同结果。

寻址同理：调度命令里的角色一律用**真名或编号**，旁人称呼只用来显示。「他认得的名字」属于扮演信息，将来由记忆那层决定玩家能认出谁；现在客户端不拿它当引用发出去——换不出编号的目标就不让选。

编排的先后（谁先谁后、什么时候推舞台与世界）属于「回合与顺位」那一层，规则不在本页。

## 浮窗：内容由外层注入

主页只放「此刻」：每张卡片都能点开，浮窗才是明细。描写类文本（环境、外观）默认不铺在主页——它们是给模型读的上下文，客户端将来用文生图表达。

出口不单独占一张卡片：从哪扇门出去属于「这个舞台」，不属于「我此刻看得见的东西」。舞台卡上只留一个计数，点开它的浮窗才把出口列成按钮。

浮窗里要取数的那一块不能由页面自己取——否则页面就不再是「只吃 props」，mock 打开浮窗时也会去连服务端。做法是把这块的渲染函数交给外层注入（`renderHistory`），容器传真容器，mock 传 fixture：页面只管「打开 / 关闭」，不关心里面的数据从哪来。这是「页面不取数」在浮窗上的延续，不是例外。

两份日志不要混：`记录` 读的是公共事件流（`game_messages`），上帝视角、带真实名字——浮窗里写了这句话；角色自己感知到的内容另有读入口 `GET /games/{game}/log`（`ActorLog`），客户端目前不展示它。这个端点是预留：它是回看用的，不是主页要的。等要做「我经历过什么」时，浮窗应该改读那份。

同理不进客户端的两样：`agent_memory_messages` 本身（记忆是模型上下文，原样摊给玩家没有意义）与传送候选列表（那是 prompt 里的省事提示，不是权限）。

## mock 目录

`pnpm dev:mock` 起一个独立入口，与正式客户端是两个 dev server、两个端口，互不影响。它列出「页面 × 状态」，每条都是可直接打开、可收藏、可贴给别人的深链接；链接里的状态名同时也是 fixture 的键，漏写一个状态编译不过。

mock 只有一条渲染路径：fixture。真数据不在这里看——正式客户端已经用同一个页面组件渲染它，而 mock 一旦也要连服务端，就多了一份要维护的鉴权、参数与失败处理，反而不像“开发用的目录”了。页面相同、容器不同，对照本来就在两个入口之间完成。

状态之外的流程也可以模拟：页面需要的动作（建局、推进回合）由容器以函数形式注入，mock 传一个假实现即可演示完整路径，而不写任何数据。

## 隔离

mock 入口是一个**独立 HTML 入口**，不是运行时开关：正式入口只加载正式入口的脚本，生产构建的输入也只有它，mock 那棵树因此在构建图之外——不是被条件编译排除，而是从未被引用。

## 与正式端的关系

mock 只需要浏览器：数据是 fixture，流程是注入的假实现，不连服务端、数据库或模型。起 mock 不需要 8787 在跑。
