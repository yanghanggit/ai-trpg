# 玩家对话审核

结论：玩家接管的 `say` / `whisper` / `announce` 在写库前经过一个**无状态审核 agent**。只有审核明确放行的台词才进入游戏；内容违规或审核不可用都不执行动作，并留下一条被拒记录。

## 边界

- 只审玩家接管的对话动作，不审 NPC 自动回合，也不审移动、攻击、使用等非对话动作。
- 只审台词正文；玩家入口里的 `reason`（内部 `mind`）不是世界内文本，不参与审核。

- `reason`（内部 `mind`）是开发期 agent / CLI 接管用的输入；正式 web 客户端的请求 DTO 不提供该字段，路由调用服务时直接省略，服务端固定使用“玩家直接提交”。这样客户端无法通过 `mind` 写入自己的叙述。
- 审核发生在“确认 actor 被玩家接管”之后、“应用计划”之前。被拒时公共事件、actor 记忆与 game version 都不改变。
- 允许的台词不落库；被拒的写入 `dialogue_blocks`。这张表就是黑名单/审计记录，不是自动封禁：不封玩家，也不按相同文本自动拦截。
- 审核失败采用 fail closed：超时、网络错误、模型错误或判定格式不合法，一律挡住本次行动。
- 内容违规返回 422 与审核理由；审核不可用返回 503 与固定的“审核暂时不可用，本次行动未执行”。两者都不消耗行动。

## 审核器

审核器是一次 completion + 一个提交工具，不是 agent loop，也没有任何 agent 记忆：

- 每次调用重新构造 system prompt 与任务消息，不读取 actor memory、历史对话或上一次判定；
- 输入只有待审台词、动作类别、角色展示名、场景展示名、世界名与该世界的 campaign setting；
- 不把 actor profile、opening briefing 或其他玩家文本交给审核器；
- 台词被明确标为“待审数据”，提示词注入不能改变审核规则。

拒绝类别：

- `immersion_break`：OOC、讨论 AI/系统/规则、要求跳出角色或忽略设定；
- `out_of_world`：现实世界的现代科技、品牌、人物或事件；
- `prohibited`：未成年人性内容、露骨性内容、仇恨与歧视、骚扰、现实违法指导、鼓励或指导现实自残等；
- `other`：其他明显不适合的文本。

虚构世界内的暴力、血腥与粗口允许。审核只在明确违规时拒绝，避免误杀正常角色扮演。

## 记录与失败

被拒记录保留游戏、actor、玩家、动作类别、目标、原文、类别、理由、模型、耗时与技术失败原因。审核通过不写记录；原文只用于人工复核与后续策略，不进入 actor 可见文本。

审核不可用与技术失败也写入同一张表，用 failure kind 与内容违规区分；两者在客户端是两种状态，但都不执行动作。

## 客户端

HTTP 接入后，客户端只需要处理两种结果：内容违规的 422 与审核不可用的 503。响应带理由、类别与 audit id，客户端展示理由即可；不要把它写成世界内事件。
