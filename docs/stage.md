# 舞台

舞台是活着的实体：有自己的 memory、生命周期与仲裁回合，也有自己的故事与环境。能力包括更新 environment、管理可交互锚点、打开通往相邻舞台的通道、向 world 发出通知，由内容为每座舞台声明；它不是 actor，也不能被玩家接管。

## 身份与记忆

舞台没有 HP、位置与自主目标，只管辖本舞台。「活着」指它能持续记忆本舞台事件、被推动时仲裁推理，不表示它会自动运行——回合完全由调用方显式推动。

它能看到本舞台内所有事件（沟通、进出、动作、死亡与自己造成的环境变化），但没有跨舞台入口：其他舞台的信息只能经 world 中转，actor 的内部 `mind` 它看不到。看到私密事件不改变 actor 的可见性。

记忆的第一条 human 消息是**开局基线**：这个舞台第一次被写记忆时的 environment 与锚点，先于任何事件落账。理由是事件日志回答不了「开局长什么样」，压缩与快照回放要的正是这个底。补写是惰性的：没被写过的舞台不付这条记忆，老局无需回填；现状仍只由回合输入拉取，不随每轮再拍快照。

读取侧有一份 stage 自己的投影；它的日志类别按本舞台的全知边界单独维护，不与 actor 共用白名单。

## Environment

`environment` 是本舞台此刻可被感知的状态，是世界面文本：不写历史、因果、角色名与角色行动。写入时统一拒绝角色名与编号引用；actor 读取时再按观察者渲染一次——在场者一定看得见彼此，不存在「看不清」的兜底。

它是拉取模型：stage 更新后不推送，actor 下一次 plan 与查看工具都读当时的快照。它与锚点及其道具的一致性目前没有代码校验，靠每轮任务文本与模型判断。

## 可交互锚点

锚点是舞台里可被角色作用的位置或部位（锁孔、门闩），道具挂在锚点上：道具不能脱离锚点存在，也没有独立的扁平列表。锚点与道具都不承载效果与后果，实际结算仍归道具效果、stage 与 world。

锚点由内容层在开局赋予，之后当舞台声明了对应的锚点动作时，由 stage 自行增删改：

- 三个动作分别是新增、移除与改写；一轮最多一次，标签舞台内唯一，总数有上限。
- 改写只换标签与描述；锚点的内部身份不变，挂在上面的道具跟着它走。
- 移除锚点会连同其上的道具一起移除；事件里记下带走了什么，避免道具无声消失。
- 锚点没有独立的状态位。某个锚点「现在能不能用、要不要先完成什么」写在舞台设定里，作为软约束由 stage 仲裁；「用掉一次就失效」也这样表达，不靠删改锚点。

拾取拿走道具，锚点留下；`pickup` 要同时给出锚点与道具名——道具地址是 (锚点, 名字)。纯装饰或根本不可操作的物体不列为锚点，只属于 environment 的散文。

## 连通性

舞台图是有向边，每条边带通行状态；`sealed` 是剧情相连但此刻过不去。范围不做对称推导，双向通行必须显式两条边：内容层决定哪些边存在，运行时只能把本舞台已有的出边从封闭打开，不能新建边。开门只改本舞台出边，不通知 world，也不改对面舞台；actor 的可去舞台只读开启的边。

## 回合

读状态与 memory → 组装本舞台可见事实 → agent loop 推理 → 暂存写动作与 world 通知 → 用终结工具提交 → 短事务内重新校验并落账。终结工具只是回合控制，常驻且不是舞台能力；环境写入是普通写动作，省略表示不改，空计划表示本轮无改动。

落账按模型给出的动作顺序执行，事件顺序随之。每个动作加入时就刷新计划快照，模型忘记终结或轮次用尽时，已暂存的动作仍会落账。写动作的上限写进任务文本，模型不必靠试错发现。

world 通知是 stage 报告，不是世界事实，也不是系统指令：它进 world memory，由 world 回合裁决。只有跨舞台与世界级后果才报告，判断必须来自本舞台已有信息。

## 事件

environment、锚点或通道实际变化才产生事件，相同快照不写；三者都进 stage memory 与公共事件流，但不写 actor memory——actor 下一次 plan 自己拉当前状态。通道事件只写起点舞台，对面舞台与 world 都不因此获得记忆；world 通知不产生公共事件，只在 world 与 stage 的记忆里各留一条。

actor 行动产生的舞台事件也进 stage memory；移动分别写起点与终点两个 stage。

## 推进与收尾

stage 回合不跟随 actor 行动自动运行，也不调用 actor loop；world 回合读取 stage 报告并裁决。只有 world 能结束游戏，结局标签由它自己命名；world 回合允许没有动作——显式提交空计划表示本轮无世界级变更，与「没提交计划」相区分。
