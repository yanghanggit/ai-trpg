# Seed 内容编写原则

内容只回答四件事：世界是什么、谁在哪里、谁能做什么、什么算公开事实。机制、格式、路由与判定归引擎；写前先做归属判断。

## 所有者

本页拥有跨剧本通用的编写原则。剧本的剧情意图、验收与删除条件在内容目录的随附 md；框架边界归数据驱动文档；名字层次归术语表。

→ 参见：[数据驱动目标](data-driven.md)、[术语表](glossary.md)

## 六个文件各管什么

| 文件 | 只放 | 不放 |
| --- | --- | --- |
| 战役文件 | 跨剧本不变的设定与职能口径 | 剧本专名、机制细节、全局规则 |
| 剧本文件 | 世界、舞台图、角色、道具、开局关系与能力 | 战役级文本、随剧本变化的知识 |
| 知识库 | 世界层面的固定事实与访问门槛 | 角色名、秘密、当前状态、可移动道具 |
| 评测集 | 与知识库一一对应的检索用例 | 与剧情状态耦合的问题 |
| 注册表 | 内容名到内容包、剧本的显式映射 | 隐式默认值 |
| 随附 md | 本剧本的意图、验收与删除条件 | 引擎规则、其他剧本的设定 |

## 落笔前的四个判断

1. **机制还是事实。** 伤害怎么算、谁能开哪扇门属于引擎；发生过什么、谁相信什么属于内容。
2. **跨剧本还是本剧本。** 换个故事仍成立写战役，随故事变化写剧本。
3. **谁会知道。** 世界常识、受限知识、角色私有信息与当前状态分属四层，不能混。
4. **会不会被当成已知。** 写进 agent 会读到的位置，就等于直接告诉它；不知道的只能来自世界内告知。

## 命名与引用

- 实体用纯名字；跨引用用稳定 key，不用展示名。角色真名与舞台名在 world 内唯一。
- 真名不是自动知识：角色设定只写该角色自己知道的名字；开局关系必须给出观察者对这个签名的称呼，其余名字只能来自世界内告知或可见记载。

→ 参见：[术语表](glossary.md)

## 每一层写什么

**世界**只写“这是什么地方、什么算收束、尺度到哪里为止”。收束条件必须在这里；舞台只能报告，不能收尾。世界能力显式声明，不依赖引擎默认。

**舞台**写它是什么、曾经发生什么、为什么重要，以及角色能从这里学到什么。环境只写当前可观察的物体、表面、光线、气味与氛围，不含历史、因果、角色名与角色行动，并与锚点及其上的道具一致。道具挂在锚点下；能力逐项声明；有向图用“没有反向边”表示单向，用“边存在但当前不可通行”表示封闭。

→ 参见：[舞台](stage.md)

**角色**设定自足、可复用：历史、性格、说话方式、手段、关系倾向、禁忌与秘密。它不绑定本局舞台与在场实体，这些连接留给开局简报；秘密放这里，不放知识库；软触发由角色自己判断，不写成状态机。开局简报写舞台、相关实体、初始目标、处境与约束，不是单轮任务，也不写工具名。

形态、外观与穿戴归外观文档。能力逐角色显式声明，只写**固有**动作；成组动作写成技艺，建局时并入角色。运行时只有“角色固有”与“道具携带”两类来源：同一个动作只能有一个出处；重复声明、把携带者动作写进角色、或依赖引擎补默认动作，内容校验都会拒绝。藏身可由技艺授予，也可直接写在角色上；声明了隐匿或藏身，就必须同时声明主动现身，自动现身只处理交互动作，不替你补动作。

→ 参见：[外观](appearance.md)、[道具](items.md)、[Actor 行动与记忆](actor-actions-memory.md)

**世界知识**只收固定事实，不收秘密、当前状态、道具位置、弱点与行为规则。一条知识要能通过三问：具备门槛的人能否通过观察、询问或公开记载知道它；角色离开或现场改变后是否仍成立；它是否只是舞台描写。写成短事实，一条一句；访问标签只表达“读不读得懂”，不是保密。

**评测**与知识库同目录维护：每条知识至少一个正例覆盖，期望文本是该条目的唯一片段，且受众读得到；没有的事实用负例守住。改文案时一起改。

→ 参见：[世界知识检索](rag.md)

## 保密与伏笔

秘密只存在于角色设定与私有记忆。知识库是世界层面的记载，不等于人人可读；舞台环境只写此刻看得见的东西。伏笔可以露在环境里，但关键事实不能提前交出——看见符文不等于知道暗语。

## 触发器与结局

暗语、沉睡、忠诚这类软触发写在角色设定或开局简报里，是意图而不是保证；不要为它们写确定性断言，但要保证前置条件可达：钥匙拿得到、门开得了、路走得通、报告发得出。故事特有的判断写进描述或推理词缀，不为单个故事新增引擎分支；不可逆的结果必须有来源与报告者。

→ 参见：[词缀](affixes.md)、[舞台](stage.md)

## 版本与验收

改内容就升版本并重新入库；开发期直接重置重刷，不做数据搬运。验收要把内容当一局游戏推演：预定路径是否可达，角色是否能学到该学的东西，公开知识是否经得起“陌生人三问”。

→ 参见：[开发期 Agent 工作流](debug-workflow.md)
