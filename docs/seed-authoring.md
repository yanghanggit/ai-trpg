# Seed 内容编写原则

内容只回答四件事：世界是什么、谁在哪里、谁能做什么、什么算公开事实。机制、格式、路由与判定归引擎。

写内容前先做一次归属判断，再落笔；判断错了，后面每一层都会漏。

## 所有者

本页拥有跨剧本通用的编写原则，任何 seed 都适用。具体剧本的剧情意图、验收口径与删除条件写在内容目录的随附 md 里；框架与内容的边界、内容入口归数据驱动文档；名字的四个层次归术语表。

→ 参见：[数据驱动目标](data-driven.md)、[术语表](glossary.md)、[世界知识检索](rag.md)

## 六个文件各管什么

| 文件 | 只放 | 不放 |
| --- | --- | --- |
| 战役文件 | 跨剧本不变的战役设定；世界职能口径是同一层的另一份文件 | 任何剧本专名、具体机制细节、全局规则 |
| 剧本文件 | 这一局的世界设定、舞台图、角色、道具、开局已知关系与能力清单；必要时按条覆盖某份职能口径 | 战役级文本、可随剧本变化的知识 |
| 知识库 | 世界层面的固定事实；常识无门槛，需要训练或出身的条目写访问标签 | 角色名、秘密、当前状态、可移动道具 |
| 评测集 | 与知识库一一对应的检索用例 | 与剧情状态耦合的问题 |
| 注册表 | 内容名到内容包、到剧本的显式映射 | 隐式默认值 |
| 随附 md | 本剧本的意图、验收与删除条件 | 引擎规则、其他剧本的设定 |

## 落笔前的四个判断

1. **机制还是事实。** 伤害怎么算、谁能开哪扇门、允许多少动作，属于引擎与工具说明；世界里发生过什么、谁相信什么，属于内容。
2. **跨剧本还是本剧本。** 换一个故事仍然成立的部分写进战役；随故事变化的部分写进剧本。
3. **谁会知道。** 世界常识、受限知识、角色私有信息与当前状态是四件事，分别落知识库的不同门槛、角色设定与舞台快照。混一层就会泄漏。
4. **会不会被当成已知。** 名字、秘密、系统路由一旦写进 agent 会读到的位置，就等于直接告诉它；不知道的东西只能来自世界内的告知。

## 命名与引用

- 实体使用纯名字：角色、舞台、道具共用同一套语法，不写类型前缀。控制面真名不能包含 `#`、空白与 `.`；角色真名与舞台名在 world 内必须全局唯一。
- 跨引用优先用稳定 key：舞台连接、角色归属、开局名字绑定都用 key，不用展示名。装备槽按道具名字引用，因为同一持有者内名字唯一。
- 真名不是自动知识：角色设定里可以出现该角色自己知道的名字；其他实体默认没有称呼，除非内容声明了开局关系，或游戏过程中自己记录。
- 开局关系必须给出观察者对这个签名的称呼；称呼可以是真名、称号、误认或关系称谓，不要求是真名。
- 开局前就已走过的舞台用 `visitedStages` 显式声明，`actor` 与 `stage` 都写 key；到访是舞台名字的唯一来源，写在简报里的名字只是散文，不会让角色认识那个地方。

## 每一层写什么

### 世界

世界设定回答“这是什么地方、什么算收束、尺度到哪里为止”。收束条件必须写在这里，因为只有世界能结束游戏；舞台只能报告，不能收尾。世界能力要显式声明，不依赖引擎默认。

### 舞台

舞台设定写它是什么、曾经发生什么、为什么重要，以及角色能从这里学到什么。环境写当前快照：此刻可观察的物体、表面、光线、气味与氛围，不含历史、因果、角色名与角色行动，并且必须与锚点及其上的道具一致。舞台道具必须写在某个锚点下，不能直接挂在舞台上：锚点是角色能作用的点，道具是它的内容。需要让舞台在运行时自行增删改锚点时，在能力清单里分别声明 `add_anchor` / `remove_anchor` / `update_anchor`；特殊锚点的前置条件（例如必须先完成某件事）写进舞台设定，交给 stage 仲裁，不额外建状态字段。内容校验会检查 environment 不含角色名字与 `#` 编号；道具名作为自然叙述可以出现，角色由舞台状态单独承载。舞台名只能点名「从本舞台走得到的舞台」（本舞台自己 + 开着的出入边对面）：还没打通的通道对面叫什么，要靠 actor 自己发现或问到，内容校验与运行时写入都会拒绝。

舞台能力逐项声明：每个舞台都能刷新环境；只有真的有机关的地方才给开通道的能力；只有跨舞台后果的源头才给向世界报告的能力。舞台图是有向的：单向用“没有反向边”表达，封闭用“边存在但当前不可通行”表达，不要指望对称推导。

### 角色

角色设定是自足、可复用的：历史、性格、说话方式、手段、关系倾向、禁忌与秘密。它不绑定本局的舞台、在场实体或当前处境——这些连接留给开局简报；同一个 actor 设定因此可以在不同舞台里“醒来”。秘密放这里，不放知识库；触发条件是软约束，由角色自己判断，不写成状态机。

开局简报是 actor 与本局的第一次连接：舞台、相关的其他实体、初始目标、处境与约束都在这里落地，不是单轮任务，也不写工具名。它允许“睡着了”“还没决定”这类状态，但这些是意图，不是保证。

签名上的 `form` 是稳定形态，统一写成 `种族:描述`，只有它进系统提示词；种子里的 `appearance` 是预制快照，建局后成为该签名的一条 `source: "seed"` 外观记录。穿戴索引与道具列表必须按名字对得上，否则换装与观察会脱节。

能力逐角色声明，但只写角色**固有**的动作。活物会说话、走动、等待；动物不操作道具；偷窃只给该会的角色。成对出现的动作写成一项技艺（`SkillDefinition`）：名字、说明与它带的动作捆在一起，建局时并入角色的动作。同一个动作只能有一个出处，写了技艺就不要再写进角色自己的动作清单。技艺是内容层的命名，不进运行时状态。武器攻击不写在这里：`strike`（单体）与 `cleave`（横扫，配 `maxTargets` 目标数）都由武器通过 `item.actions` 提供，武器穿戴中才生效；内容校验会拒绝把这两类动作写进 `actor.actions`。身体攻击 `brawl` 同样是固有动作，给谁由内容决定——引擎不会因为武器槽为空就自动授予它，空手时能不能打完全看这一条声明。语言与发声规则属于该角色，不属于全局规则。

### 世界知识

一条知识要能通过三问：一个具备该门槛的人能否通过观察、询问或公开记载知道它；角色离开或现场被改变后它是否仍然成立；它是否只是舞台描写或当前状态。任一答案为否，就不入库。

知识写成短事实，一条一句，按稳定分类归档。它不承载角色秘密、道具位置、弱点与行为规则。多数条目是常识；需要训练、识字或职业出身的条目写访问标签，actor 用 `knowledgeAccess` 声明自己具备的标签。门槛只表达“读不读得懂”，不是保密：有权限的角色照样可以在对话里说出去；必须永不外传的事属于角色秘密。

一条知识只取一个访问标签集合，任一标签命中即可读；同一段正文不能出现两个门槛。内容用到的标签至少要有一个 actor 持有，actor 声明的标签也至少要被一条知识用到。分类名会随检索结果渲染给模型，所以只能是中性主题，不能叫“秘传”或“院长密令”。

### 评测

每条知识至少有一个正例覆盖，正例的期望文本必须是该条目的唯一片段，且用例的受众必须读得到这条知识；没有的事实用负例守住。评测与知识库同目录维护，改文案时一起改。

## 保密、伏笔与“世界内已知”

秘密只存在于角色设定与私有记忆。知识库是世界层面的记载，不等于人人可读；舞台环境只写此刻看得见的东西。伏笔可以露在环境里，但关键事实不能提前交出——看见符文不等于知道暗语。

开局名字绑定声明世界内已经认识谁，并给出观察者对这个签名的称呼；其余名字必须靠自我介绍、他人介绍或可见记载获得。不要用“所有人都知道”这种叙述去要求引擎替你兜底：要么声明一条边，要么保持未知。

## 触发器与结局

暗语、沉睡、忠诚这类软触发写在角色设定或开局简报里，是意图而不是保证；不要为它们写确定性断言，但要保证前置条件可达：钥匙拿得到、门开得了、路走得通、报告发得出。

词缀是声明式的，故事特有的判断写进推理词缀或描述里，不为单个故事新增引擎分支。武器要能被用来挥击或横扫，就同时声明对应动作（`actions`）与至少一条同名词缀（`affixes.strike` / `affixes.cleave`）；横扫还要写 `maxTargets`（目标数，≥ 2）。无条件的数值写静态，条件判断写推理。内容校验会拒绝其它组合。任何不可逆的结果都要有来源与报告者：谁造成了它，谁有权收尾。

## 版本与验收

内容版本与知识库集合绑定：改内容就要升版本并重新入库；开发期直接重置重刷，不做数据搬运。

验收不只看单元测试，还要把内容当一局游戏推演一遍：预定的路径是否真的可达，角色是否真的能从内容里学到该学的东西，公开知识是否经得起“陌生人三问”。护栏由内容测试、框架专名守卫、系统提示词工具名守卫与检索评测共同承担，细节以它们为准。

→ 参见：[开发期 Agent 工作流](debug-workflow.md)

## 反模式

- 把机制、格式或工具名写进战役文本。
- 把舞台描写、当前状态或角色秘密写进知识库，或把知识门槛当成保密手段。
- 用展示名当跨引用键，或在名字里写类型前缀。
- 让舞台替世界收尾，或让角色替舞台决定环境。
- 声明了能力却没有对应的内容路径，或写了路径却没有声明能力。
- 依赖引擎默认行为：不声明动作、不声明能力、指望对称边自动成立。
- 为软触发写确定性断言，或为了测试去硬编码剧情结果。
