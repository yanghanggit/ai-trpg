# 物品

物品由三件事定义：大类、声明式效果与穿戴索引。大类决定能进哪个槽位，效果决定被使用时发生什么，穿戴索引记录它此刻是否在身上；三者互不推导。

→ 参见：[Actor 行动与记忆](actor-actions-memory.md) → 参见：[外观](appearance.md)

## 大类

共六类：`weapon`、`equipment`、`accessory`、`consumable`、`valuable`、`material`。前三类可穿戴，各自只能进对应的一个槽位；后三类永远不进入穿戴索引。除穿戴校验外没有任何规则读大类：可见性、能否被偷、数量语义都不按大类分叉。

- `consumable` 的数量语义尚未落地（使用不扣减），`valuable` 没有价值或交易系统，两者目前只是提示词里的标签。
- `material` 是尸体留下的物理素材：效果固定为 `none`，没有战斗数值，不进槽位，也不能被 `use`。它多一个 `source` 字段，记着源于哪个角色，随物品换手保持不变，只有 `material` 可以声明它。
- 提示词里大类以英文枚举值出现，没有中文标签；槽位才有中文标签。

## 词缀

词缀是物品上的一句自然语言规则：条件是否成立、效果到什么程度，交给推理端判定；结算只做追加，不改变物品的声明式效果。每条词缀带一个短名字，展示与提示词统一成 `[名字]内容`，轨迹、观察与提示词里都能一眼看出是哪条规则在起作用。

→ 参见：[架构与契约](architecture.md)

## 可见性：三个通道

可见性是「能查到」，不是「已经知道」——系统不会把物品清单写进 system prompt。

| 通道 | 范围 | 能查到什么 |
| --- | --- | --- |
| 自身 | 本人 | 名字、大类、数量、描述、物品级 damage / block、是否穿戴 |
| 同场景感知 | 同场景的其他角色，含尸体 | 与自身相同的清单；不含对方的角色属性与生命 |
| 场景陈列 | 全世界任意场景 | 尚未被拾取的场景物品：名字、大类、描述 |

持有者视角没有隐藏物品：同场景即可看全背包。场景陈列对 actor 全局可查，不必到现场；stage 小 GM 的查看工具限定本场景，它不读角色背包，只从场景事件记忆里知道物品名；世界叙事者连物品名都看不到。物品一旦被拾取就离开场景陈列，进入持有者的两个通道。

## 转移与偷取

四种动作触及物品：`pickup`（场景 → 自己，公开）、`give`（自己 → 同场景角色，含尸体，公开）、`steal`（同场景角色 → 自己，私密）、`use`（不转移）。`give` 与 `steal` 都会清理交出方的穿戴索引，物品行本身不动。

`use` 只作用于背包里没穿戴的物品：槽里的物品不能使用，武器归 `attack`，其余是被动装备，要用就得先卸下。这样「在槽里」与「在包里」唯一决定可执行的动作，攻击与使用不会重叠。

背包里没穿戴的武器仍然是合法道具：同一件东西既能当武器也能当工具（火把既能打也能点东西）。这种双用途是有意保留的——「这件东西还能怎么用」交给模型判断，比按大类预先封死更有创作空间，所以划界只用槽位状态，不按大类。

`steal` 只有三个条件：同场景、名字精确匹配、目标活着时不能拿正被穿戴的物品。保护来自穿戴索引，不来自大类：未被索引的物品一律可偷，所以随身携带的 `consumable` 与 `valuable` 与摊在桌上没有区别，尸体则完全没有保护。数量也不参与判定：转移整行，没有部分窃取。小偷已持有同名物品时转移直接失败——`steal`、`give`、`pickup` 共用这条命名唯一约束。

## 谁知道发生了什么

`pickup` 与 `give` 是场景公开事件。`steal` 的公共消息是 private，但受害者一定收到「被取走」的通知，stage 记忆也会留下场景事件——**没有无声的窃取**：受害者与场景小 GM 都会知道，旁观角色不会。

## 掉落

`material` 是框架唯一会主动创造的物品，只有一个入口：死亡阶段。死者宣布死亡、写好尸体外观之后，掉落推理读尸体与当前场景，产出 0–2 条材料写进**尸体的背包**，不是场景；`source` 由框架填成死者名，不交给模型决定。理由很直接：尸体本就是可搜刮对象，材料放在尸体上走已有的 `steal` 通道，不需要 `pickup` 参与。

约束写在工具定义里：只写尸体本身的物理产物（毛皮、牙、骨、鳞、血、绒、残渣），不写武器、钥匙、信件等剧情物品——那些是尸体原有的背包。同名材料并进已有那一行，同名但不是材料则跳过。

掉落的幂等来自死亡认领本身：一次死亡只宣布一次，也就只掉一次；重推尸体外观不会再次掉落。
