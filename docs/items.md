# 物品

物品由三件事定义：大类、按触发声明的词缀与穿戴索引。大类决定能进哪个槽位，词缀决定挥击与使用时发生什么，穿戴索引记录它此刻是否在身上；三者互不推导。

→ 参见：[Actor 行动与记忆](actor-actions-memory.md)、[外观](appearance.md)

## 大类与词缀

大类只负责槽位：前三类可穿戴且各自对应一个槽，其余永远不进入穿戴索引；除穿戴校验外没有规则读大类——可见性、能否被偷、数量语义都不按大类分叉。材料是例外的一条：它是尸体留下的物理素材，不携带词缀，多一个随物品换手不变的来源标记。

挥击与使用各自声明词缀，动作侧只负责授权、目标解析与基础事件；一个动作最多引用一件物品，后果全部由词缀承担，物品不再有独立于词缀的默认后果层。

动作按来源分两类：**固有动作**写在角色身上（说话、走动、肉搏、偷窃……），**携带者动作**只由穿戴中的物品授予，角色不能固有声明。内容层还给固有动作一种成组写法：一项技艺（`SkillDefinition`）把几个动作捆在一个名字下，建局时并入固有动作——它只是写法上的分组，运行时仍然只有这两类来源。哪些大类能携带哪些动作由一张表决定（`CARRIED_ACTIONS_BY_ITEM_KIND`），现在只登记了武器；新增携带者只加一行，内容校验、工具装配与授权合并同时生效。物品行的动作因此不是"能力备注"，而是借给穿戴者的授权，卸下即收回。

武器上的两个攻击动作只差目标数：`strike` 恒为单体，`cleave` 用同一把武器一次命中多个目标，上限来自武器自己的 `maxTargets`（目标数）。两者各自声明词缀：`cleave` 读的是 `affixes.cleave`，不借用 `affixes.strike`；同一个动作最多引用一件物品，后果全由自己那个触发的列表承担。横扫逐目标各结算一次，每个目标各自减一次防御、各自写一条命中。内容形状是 `actions: ["strike", "cleave"]` + `affixes.cleave` + `maxTargets ≥ 2`，三者缺一都会拒绝；没有 `cleave` 的武器写多目标上限也会被拒绝（单体挥击不需要它）。推理词缀阶段目前按「一个动作一个目标」建模，因此横扫只跑静态词缀。

静态词缀由引擎纯计算，带条件的判断交给推理端；伤害如何求和与减伤、命中何时产生，归[词缀](affixes.md)所有。

→ 参见：[词缀](affixes.md)、[数据库](database.md)

## 可见性

可见性是「能查到」，不是「已经知道」：物品清单不进 system prompt。本人、同场景与场景锚点三个通道的边界归信息披露；物品自己的规则只有两条：物品名是公共标签，不做知识隔离，但「在哪里、在谁身上」必须进入对应观察范围；物品被拾取后离开它所在的锚点（锚点留下），进入持有者的通道。

场景物品的作用域是锚点：同一场景的不同锚点可以各放一件同名物品，所以 `pickup` 必须同时给出锚点与物品名。

→ 参见：[信息披露](information-disclosure.md)

## 转移与搜刮

五种动作触及物品：`pickup`（锚点 → 自己，公开）、`loot`（同场景尸体 → 自己，公开）、`give`（自己 → 同场景角色，含尸体，公开）、`steal`（同场景活人 → 自己，私密）、`use`（不转移）。取物的三条通道按对象分工：躺在地上的走 `pickup`，躺下的人的走 `loot`，还站着的走 `steal`。三者都只改归属；背包里已有等价物品时并入 `count`，物品签名不变。

`loot` 与 `steal` 的差别在对象、保护与手法：`steal` 只看同场景、名字精确匹配、目标活着时不能拿正被穿戴的物品；`loot` 的对象必须已经死亡，尸体没有穿戴保护，武器、护甲与材料一视同仁。搜刮默认搬空尸体（背包没有上限，逐件取走只是噪声），也可以只点名单上的几件；点名时整批先校验，缺一件就整次不成立。搜刮不校验击杀归属：尸体是公共对象，谁先到谁搜；要收窄成「只有击杀者能搜」，得先有击杀记录，那是另一套机制。数量不参与判定，转移整行。一个作用域里物品名只有一行：等价的东西并入 `count`，同名但不是同一件则直接失败——`steal`、`loot`、`give`、`pickup` 共用这条约束。

`inspect` 与 `steal` 都要过敏捷这一关：查看只在自己比目标敏捷时不留痕迹，否则目标知道有人在看他的东西；窃取要求不比目标慢——慢了摸不到，快过目标无声无息，恰好持平能得手但对方会察觉。比的是双方当下的敏捷（穿戴加成算在内），对方的数值不公开，只能靠试；尸体不会察觉。查看的清单只回给查看者，窃取与查看的公共流仍是上帝视角。

`use` 只作用于背包里没穿戴、且声明了使用词缀的物品：槽里的物品不能使用，武器归 `strike`，其余是被动装备。这样「在槽里」与「在包里」唯一决定可执行的动作，挥击与使用不会重叠。背包里没穿戴的武器仍是合法道具：同一件东西既能当武器也能当工具，这种双用途是有意保留的——两条触发各自声明即可。

## 谁知道发生了什么

`pickup`、`loot`、`inspect` 与 `give` 是场景公开事件；`steal` 的公共消息是 private。被察觉的那次，对方与在场者才会知道；无声的那次只留在上帝视角的事件流与场景记忆里——场景小 GM 全知，但它不会替角色说话。就算被察觉，旁人看到的也只是「有人翻看过」，物品清单只进查看者自己的行动事实。旁观角色是否知道仍由信息披露的范围决定。

→ 参见：[信息披露](information-disclosure.md)

## 掉落

`material` 是框架唯一会主动创造的物品，入口只有死亡阶段（`src/game/death/drop.ts`）：掉落推理读此刻的可见外观与所在场景，把材料写进死者背包而不是场景，来源由框架填。理由很直接：尸体本就是可搜刮对象，材料跟着尸体走，不需要 `pickup` 参与。同名材料并进已有行；掉落的幂等来自死亡认领本身，一次死亡只掉一次，失败不补账。

→ 参见：[数据库](database.md)
