# 行动顺位

行动顺位是「此刻谁先行动」的**快照**：开一张时把全世界还能行动的 actor 按敏捷现值排成一条次序，之后每次推进某个 actor 的回合，就给他在这张单上的行动次数加一。

它不是回合本身，也不决定下一个该推谁。回合由调用方点名推动，顺位只记账——没有进行中的顺位时推进照旧，只是不记数。这条边界让顺位可以先独立存在，再由将来的调度使用它。

## 快照

排序在开单那一刻一次性算完，落库的是当时的敏捷现值（本体 + 穿戴 + 状态效果，与面板、察觉同一份口径）与名次；之后换装、加状态都不回写。死者不进入顺位：他这一轮已经不能行动，进来只会留下一条永远不动的计数。

并列按实体序号升序兜底，不按名字——名字会变，同值必须可复现。排序口径与它的开关归玩法数值层，顺位只消费「已经排好的次序」。

序号从 1 起、同单内连续，是这张单自己的位置，与世界内的实体序号无关。

## 计数与生命周期

一次推进只在**落账成功**时加一：模型跑完但计划被拒的那一轮不算行动——判据取自行动事实，被拒的计划不留下任何行动事实，也就没有「做过」可记。建单之后才加入世界的 actor 不在名单里，推进他只会静默跳过——快照不追认新人。

一局同时最多只有一张进行中的顺位，这是存储层的硬约束，不是调用约定。完成给它打上标记与完成时间，之后不再记数；移除直接删行，条目随外键级联，不留归档。已完成再完成、移除不存在的顺位都明确失败，调用方得以确认自己这一步有没有落到状态上。
