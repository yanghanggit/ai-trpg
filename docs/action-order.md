# 行动顺位

行动顺位是「此刻谁先行动」的**快照**：开一条时把全世界还能行动的 actor 按敏捷现值排成次序，之后每推进某个 actor 的回合，就给他的回合计数加一。

它是时间轴上的一环：推进按顺位走，一条顺位走一遍是行动轮，轮里每个角色各有一个回合（词义归[引擎概念用词](terminology.md)）。计数回答「轮到哪了」，刻度由**时刻**给出。

顺位不推动任何回合：推谁、推几次、何时收工都归调用方；没有进行中的顺位时推进照旧，只是不记数。

## 快照

排序在开顺位那一刻算完并落库：当时的敏捷现值（本体 + 穿戴 + 状态效果，与面板、察觉同一份口径）与名次，之后换装、加状态都不回写；死者不进入顺位，他这一回合已经不能行动。

名次不分玩家与 NPC：主角、被接管者与由引擎跑循环的 NPC 都是同一个回合；生死与执行方不落库，读出时补。并列按实体序号兜底，同值必须可复现。

## 计数与时刻

计数发生在**回合**上：有行动落账算，调用方明示的空回合也算；被拒的计划不留下行动事实，也不占时间。计数只在回合级入口上发生——点名 NPC 与玩家提交动作各算一个回合，两路同一口径；两条入口都先入队再执行，入队不等于回合发生过。

**时刻**是本局的时间，不是这条顺位的：每落账一个回合（角色、舞台、世界任一层）加一，开局为零；被拒的回合不推进，顺位收工、删掉、重开都不影响。规划读到某一刻的世界，这一回合落账后进入下一刻——提示词里的「现在」与记忆里的事实分别写着这两个数。时刻只前进，不是墙钟时间、动作数或回合计数；它归局，顺位只在自己的投影里带出读出这一刻的值。

## 生命周期

一局同时最多一条进行中的顺位，是存储层硬约束。完成打标记与完成时间，之后不再记数；移除删行，条目随外键级联。完成是收敛，重复完成回同一行；移除相反，删过的 id 再删就是不存在。开顺位后加入的 actor 不在名单里，推进只会静默跳过；之后死掉的人留在名次上，计数保留但不再被选中。

## 客户端驱动

服务器持有数据，客户端持有执行权：服务器不代选目标、不在推进之间插调度，只回答「谁快轮到」并在推进发生时记录。「谁快轮到」有唯一定义——计数最少者，同值取名次靠前，候选是还活着的人——读出时连同 `control` 一起给出。

`control: "player"` 的回合等人拿主意，`"agent"` 的交给引擎跑循环；两者都计数，接管与放手只改 `control`。人不动手时客户端替该席位记一个空回合，人会往队尾沉一次。`alive` 逐条给出，所以「走完一遍」也能看活着的条目计数齐平——但齐平只是读出的一刻，不是状态；想知道这一轮的 world 推过没有，读**回合账**。

## 回合账

回合账（`action_order_turns`）是顺位下的一张只追加表：每落账一个回合记一行，`kind` 记层次（`actor` / `pass` / `stage` / `world`），`round` 记它属于哪一行动轮，`subject_name` 记当时的名字，`stage_id` 记角色落账时所在的舞台。角色行另带对账三元组：顺位期望的名次、实际名次、是否一致（不在顺位上时留空）。

它补的是两件此前只能靠齐平去猜的事实：某一行动轮里，某个**舞台**推过没有、**world** 推过没有。world 回合不改任何计数，所以它此前在数据里不存在。

读出来的是**行动轮**（`round`）：最近一笔账所属的那一轮、它的角色 / 舞台 / world 三项状态；与顺位并列下发，不嵌在顺位里。编号由账上 world 行的数量决定，所以「推完 world 之后仍报这一轮」是一个稳定读数，不会被下一次推进清零。

边界与顺位、`dispatch` 同一条：**账是记录，不是回合的前置条件**。写入点是回合落账处（角色两路、舞台、世界各一处），写不进去不影响回合；引擎不判「本轮结束」，也不拒推错人，什么算收尾仍由调用方定。

服务器只拒两件事：视图过期（入口带客户端读到的世界版本，在执行开始时比对，拒绝拿旧视图做决定）与同一局并发推进（同时只允许一个回合在跑；互斥在库里，空回合不占位）。一次编排周期没有事务，中途失败时前面已落账的留在库里；玩家空位不阻塞——服务器没有「等待玩家」的状态。「推了不该推的人」不拒，只在轨迹与回合账里各留一条对账事实，只陈述、不判罚。

一条边界：计数只在这条顺位之内，删掉即清零；时刻跟着局走，不随顺位清零。
