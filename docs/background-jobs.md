# 后台作业队列（jobs）

本模块只提供后台作业基建：持久队列、worker、状态快照与等待。它不含 HTTP 路由，也不认识业务；具体作业由业务侧显式注册。

## 命名

统一用 `job` / `jobId`：一行作业同时是概念与执行实例。`task` 留给 Node 与测试语境里的「异步任务」，本模块不用它。

## 选型

自建最小队列，不引入第三方队列运行时：队列表与串行键索引都由本仓维护，迁移与 schema 的所有权只归 Drizzle。只继承外部队列的设计目标（持久、租约、重试），不继承其运行时与迁移机制。

→ 参见：[开发规范](conventions.md)

## 设计目标

长耗时工作不占 HTTP 请求：入口只入队并返回 `jobId`，worker 在请求生命周期之外消费。队列持久化在项目既有的 PostgreSQL，进程重启不丢；状态、最后一次错误与结果同行，不另设错误旁表。

变化要能被看见：每一次状态变更都广播一次，客户端因此可以轮询、也可以订阅，而不是靠猜。

## 性能位置

这类队列的容量最终都受 PostgreSQL 限制；pg-boss 不会突破数据库上限，只提供更完整的功能与运维手段。本项目的作业模型是长耗时 LLM pipeline，并发受串行键约束，数据库写入不是瓶颈。若未来出现大量短作业、多 worker 争抢或历史作业堆积，再评估 pg-boss / graphile-worker 或专用队列；届时优先调整索引、批量领取与归档，而不是先换库。

## 队列语义

`queue` 只用于 worker 分流；`serializationKey` 表达「同一房间 / 同一世界的 pipeline 不能并发」：同一 queue + key 的活跃作业最多一个，终态释放键。约束放在数据库唯一索引，而不是依赖调用方自觉。

worker 用租约与心跳处理进程失联，避免同一作业被两个 worker 同时执行；重试与不可重试由作业定义和 worker 共同决定。查询拿到的是快照，等待终态不依赖进程内事件，所以多 worker / 多进程看到同一份真相。

## 进度

执行中的 handler 可以自己报阶段，落在同一行的 `progress` 上（`step` 加一句可选 `detail`）。

只允许放「这一步在做什么」，不许放业务状态：作业行不该成为第二份世界。每次上报就是一次 UPDATE，所以进度天然被轮询、订阅与补发看见，不必另开一条通道。

粒度由 handler 决定，作业层不规定台阶。回合作业的做法是「阶段 + 轮次」：`planning` 每轮重报一次、附一句「第 2/4 轮」，`applying` / `finalizing` 各报一次——一轮就是一次模型调用，这是能给出的最细粒度。

上报是尽力而为：写失败只记一行日志，不让一个已经跑起来的作业因为报进度失败而失败。

## 取消

取消分两种，边界清楚：

- **还没开始**：`pending` 的作业当场撤成终态 `canceled`，串行键释放，同一组可以立刻入队下一条。
- **正在执行**：置 `cancel_requested`，worker 每秒读一次，在下一个检查点中断。中断打的是同一个 `AbortSignal`，所以**正在等的那次模型调用会被真正掐断**，不是干等它返回。

检查点由业务侧定，作业层只负责「把取消翻成一次 abort」。判断标准是「能不能安全停」：进入写事务之后就不该再停——落账不幂等，半途停下会留下半份世界。所以业务侧在落账开始处关掉「可撤窗口」，之后到达的取消请求被忽略，作业照常以成功结束。

`cancel_requested` 写在库里而不是进程内，因为 worker 可能在另一个进程；一秒轮询一次按主键的查询，换来的是「点取消后一秒内停下」。

## 状态推送

状态变更通过 PostgreSQL 的 `LISTEN/NOTIFY` 广播，不另设事件表。

1. 通知只是「去看一眼」的信号，真相是那一行。通知丢了、进程重启了、客户端断线了，重连后按 `updated_at` 重查就能补回来——推送永远只是加速器。
2. 通知里只放「谁变了」与它属于哪一组；要内容就回库里按主键读，推出去的东西与查询永远同源。
3. 走数据库而不是进程内事件：worker 与 API 可以分进程，多个实例各自服务自己的观众。

`updatedAt` 同时是去重依据与补发游标。同一作业在极短时间里多次变更时，推送可能合并成一条——事件是快照，不是流水账。

## 接入边界

HTTP 接入只做三件事：入队并返回 `jobId`、把快照 / 等待 / 按组列表暴露成路由、把状态变更转成 SSE。handler 永远不在路由请求里执行。业务作业在显式注册点登记，worker 不认识未注册的 kind，直接失败——不做目录扫描或隐式导入。

→ 参见：[架构与契约](architecture.md)、[回合作业](turn-jobs.md)

## 暂不包含

执行中的取消、作业归档与清理都还没有：作业行暂时永久保留，开发早期回看比省空间重要。推送只覆盖作业行本身，不推送世界状态。
