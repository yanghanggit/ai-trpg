# 外观（appearance）

外观是运行时动态量，不是身份。稳定视觉数据是签名上的 `form`，可见外观是 `appearances` 里的一条渲染记录：两者分层，换装只动后者。

## 模型

- `actor_signatures` 存稳定形态，一个 actor 同时只有一条在用的签名。`form` 统一写成 `种族:描述`，种族不加方括号——导出 Markdown 时方括号会被当成链接引用定义。换装不改写 `form`。
- `appearances` 是 append-only 渲染记录：每个签名只有一条当前记录，历史不覆盖、不删除。`ActorState.appearance` 只带展示文本与那条记录的 id，供追溯来源。
- `equipment` 是槽位到物品名的索引。物品不知道自己被谁穿着，穿戴状态只由 actor 维护。

## 签名

「可被看见的样子」是通用机制：换装追加记录；伪装、变身这类改变**身份可辨识性**的行为开一条新签名并封上旧的，于是认识旧签名的人看到新签名时认不出他。签名之间没有「本相 / 变体」语义，它们只是同一个 actor 的不同形态——面具、法术、诅咒这些说法由内容写在物品与设定里，引擎不为某个故事增加 apply 分支。

actor 的 system prompt 用**开局签名**的 `form` 快照：跟着换装重写，会让「宪法」随每次换装漂移。

→ 参见：[术语表](glossary.md)

## 推理

入口在 `src/game/appearance/`，两个任务各写各的任务文本，共用一把提交工具 `submit_appearance`：

- `update`：按 `form` 与槽位解析出的穿戴重新生成。不给旧外观，免得模型复述旧值。
- `death`：以刷新前的那份外观为底座（`base`），只给姿态、表面与结构三个维度。「死亡」「尸体」是跨题材通用的状态词，可以留在引擎；材质与痕迹的说法不点名——血还是漏液由形态与记忆决定。也不写穿戴掉落在哪、周围留下什么：那是引擎没有的机制，写进提示词等于教模型编造。

两边共用的约束：

- 输入只到「角色自身」为止：不注入 stage 的 `environment` / `profile`，也不开放 `query`。外观是数据快照，追环境的实时变化没有稳定终点——「淋湿」要再推导「换到干燥场景后变干」，推不完。
- 战役设定与全局规则由 actor 的宪法携带，任务输入不重复下发。
- 饰品（`accessory`）不参与：这个大类的语义随题材漂移，引擎只保留槽位与穿戴索引，外观只消费武器与护甲。内容定义因此渗不进引擎。
- 提示词接在借来的记忆后面，所以一律用「你」称呼当事人；产出是第三人称、不带名字的可见描述，名字与引用由 `assertWorldFaceText` 拦下。
- 推理不写 memory，也不改 system prompt。
- 失败不写记录，当前外观保持不变。

外层看到的变化要不要写成事件，由入口决定，不做成开关：`updateAppearance` 写（自己一条用「你」，同场景他人各一条用观察者相对的称呼或 `#编号`）；`rebuildAppearance` 与 `refreshCorpseAppearance` 不写——前者是维护性重推，输入没变就不该产生事实；后者的通知已由死亡宣布覆盖。

## 来源快照

每条运行时外观都存下生成那一刻的完整输入（prompt、任务文本、结构化摘要、底座），为的是复盘与必要时重放。`source` 只区分 seed 与 runtime；具体是换装、死亡还是维护性重推，由任务与穿戴快照判断，不维护触发原因枚举。

## 换装入口

`equip` / `unequip` 在事务内只改索引；调用方提供外观服务时，`applyActorPlan` 在事务提交后补一次外观推理，失败只记日志、不回滚已落账的穿戴。于是换装是「规划 + 外观」两个 loop，玩家接管路径没有规划 loop，只有外观。

批量维护不在这里：`agent:game appearance --all` 在 CLI，读全表、按生命状态分流，活人逐个重推，尸体留给死亡阶段（那时才有尸体描写，且由收尾标记保证只写一次）。本模块只负责被点名的那一个 actor。

→ 参见：[物品](items.md)、[数据库](database.md)

## 死亡

死亡阶段用 `death` 任务刷新外观，结果写回同一签名，只跑一次；推理失败就保留生前最后一条记录，并记下待补的标记。

它不写外观变化事件：宣布阶段已经通知过全场与死者自己，再贴一条只是同一个事实说两遍。

## 种子数据

种子里的 `signature.appearance` 是预制结果，等于提前跑过一次推理：建局时成为该签名的第一条 seed 记录，运行时换装再追加。它遵循与运行时相同的输入规则（`form` + 非饰品穿戴 + 剧情痕迹）。

不写预制外观的 actor 回退到 `form`，也没有穿戴。

→ 参见：[bell-monastery.md](../apps/server/seeds/dark-fantasy/bell-monastery.md)
