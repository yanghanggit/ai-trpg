# 属性与终值

## 结论

`Stats` 是全局唯一的数据块：所有可能出现的属性都在同一个形状里，角色、物品、数据库行与运行时状态共用。这是有意的——跨宿主永远对齐，一份校验形状、一个存储列、一条相加规则、一套中文名，不需要为每种宿主另起一套字段。

形状统一不等于语义统一。字段按所有者分成两类：

- **源属性**：`maxHp`、`strength`、`wisdom`、`agility`。角色拥有它们，内容把它们写进角色。
- **终值**：`damage`、`block`。物品拥有它们——武器的伤害、护甲的格挡是写死的固有值；角色**不存终值**。

→ 参见：[玩法数值](gameplay.md)

## 一次结算的顺序

1. 角色用自己的源属性换算出顺时的 `damage`：力量进伤害，智慧与敏捷目前不产出这两个数。`block` 不由源属性产出——防御完全来自穿戴，角色自身的源属性不给格挡。
2. 与正在穿戴的物品核算：装备固有的 `damage` / `block` 逐项加进来。
3. 之后只有 `damage` 和 `block` 参与结算：合计的 `damage` 是攻击力，合计的 `block` 是格挡，减伤只发生一次。

对角色来说，`damage` 与 `block` 都是**顺时输出**：结算那一刻算出来，用于展示与后续加法，用完即弃，不写回角色。角色身上的这两个字段因此恒为 0——内容写了会被校验拒绝。

## 谁写什么

- **角色**：内容只写源属性；源属性可被装备加成。终值不写，结算时现算。
- **物品**：终值是内容写死的固有值，只在核算那一步相加；若写源属性，那是对穿戴者源属性的加成。

源属性只由内容与装备提供，不能从终值倒推：角色不会因为带着一把高伤害的武器而变强，武器只在核算那一步贡献自己的终值。

角色内容里写终值会被校验拒绝：写了却不生效是静默错，宁可解析失败。词缀能引用的数值因此只有 `attack`（结算期现算）与 `item.damage`（物品终值原值）。
