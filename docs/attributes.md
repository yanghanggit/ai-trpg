# 属性与终值

## 结论

`Stats` 是全局唯一的数据块：所有可能出现的属性都在同一个形状里，角色、道具、数据库行与运行时状态共用。这是有意的——跨宿主永远对齐，一份校验形状、一个存储列、一条相加规则、一套中文名，不需要为每种宿主另起一套字段。

形状统一不等于语义统一。字段按所有者分成两类：

- **源属性**：`maxHp`、`strength`、`wisdom`、`agility`。角色拥有它们，内容把它们写进角色。
- **终值**：`damage`、`block`。道具拥有它们——武器的伤害、护甲的格挡是写死的固有值；角色**不存终值**。

隐匿不是属性：它不进 `Stats`，是 actor 的运行时状态（见[信息披露](information-disclosure.md)）。属性是可加的数值潜力，隐匿是随动作变化的感知条件，两者不能混在同一份形状里。

→ 参见：[玩法数值](gameplay.md)

## 一次结算的顺序

1. 角色用现值的源属性（本体 + 穿戴加成 + 状态效果）换算出顺时的 `damage`：力量进伤害，智慧与敏捷目前不产出这两个数。`block` 不由源属性产出——防御完全来自穿戴，角色自身的源属性不给格挡。
2. 与正在穿戴的道具核算：装备固有的 `damage` / `block` 逐项加进来。
3. 之后只有 `damage` 和 `block` 参与结算：合计的 `damage` 是攻击力，合计的 `block` 是格挡，减伤只发生一次。

对角色来说，`damage` 与 `block` 都是**顺时输出**：结算那一刻算出来，用于展示与后续加法，用完即弃，不写回角色。角色身上的这两个字段因此恒为 0——内容写了会被校验拒绝。

## 谁写什么

- **角色**：内容只写源属性；源属性可被装备与状态效果加成。终值不写，结算时现算。
- **道具**：终值是内容写死的固有值，只在核算那一步相加；若写源属性，那是对穿戴者源属性的加成。

在穿道具的 `damage` / `block` 一律逐项计入，不按大类筛选：武器给的格挡、护甲给的伤害同样生效，内容侧也没有对应校验。引擎只认「在穿」，要不要这么写由内容自己克制。

源属性只由内容、装备与状态效果提供，不能从终值倒推：角色不会因为带着一把高伤害的武器而变强，武器只在核算那一步贡献自己的终值。

角色内容里写终值会被校验拒绝：写了却不生效是静默错，宁可解析失败。词缀能引用的数值因此只有 `attack`（结算期现算）与 `item.damage`（道具终值原值）。

→ 参见：[玩法数值](gameplay.md)

## 状态效果

状态效果是属性来源的第三个宿主：它写在角色内容里，建局时物化进 actor 行，之后与本体、穿戴一起逐字段相加。它不是属性本身——一个角色可以带着若干条效果，每条只带一份属性调整，所以效果不进 `Stats`。

v1 只有「在场即生效」这一种语义：没有施加与移除，没有时长，也不由推理判定。能调整的只有有结算读点的源属性（力量与敏捷）；终值属于道具，智慧与生命上限没有读点，内容写了会被校验拒绝，和角色自带终值同一个口径。

它和词缀是同类东西的两个宿主：词缀挂在道具上、按动作触发并产出一段结算；状态效果挂在角色上、不触发，只改现值。因此它没有触发清单与见证，旁人也不可感知。时长与施加要等「一局怎么计时」定下来再谈，现在不在类型里占位。

→ 参见：[词缀](affixes.md)

## 结算快照

结算的第一公民是一份快照：动作开始时把角色读成只读值——换算后的属性、当前生命、动作发生前的隐匿、死亡是否已收尾——此后结算不再回库。发起者生成一次并交给每个目标共用，目标各自再取一份自己的快照；两份快照相遇才产出结果。状态变化之后再动角色，也不会回头改写已经生成的快照。

快照自带该次结算解析出的完整规则配置，不引用全局开关：回放读快照里的值与规则，不读当前代码常量。规则新增读点（按生命差加成、吸血之类）时，把读点加进快照与规则配置，而不是在结算中途再查库。

结算是纯计算，产出带角色语义的有序效果列表；落账逐条写，每条自己按账本截断。治疗只认死亡收尾标记，不认生命值——生命归零但未收尾的仍可被救回。

→ 参见：[词缀](affixes.md)
