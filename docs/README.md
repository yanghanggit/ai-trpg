## 写作约束（AI 编写文档时必须遵守）

总纲：**代码是唯一事实源；文档只写代码写不出来的部分。** 以下规则都是这条总纲的推论。

### 内容

1. **只写意图与关系。** 为什么这样设计、放弃了什么、系统之间怎么接、产物被谁消费。步骤、字段、默认值与函数行为由代码自述，不复述。
2. **删除测试。** 一段话删掉后设计意图仍然完整，就必须删；文档的默认动作是删，不是加。
3. **符号只做锚点。** 领域类型名、文件名与命令可以直接引用；变量名、函数名、字段名只在需要定位时出现，不拿来代替解释——把符号删掉，这句话仍要读得通。
4. **一篇一个系统。** 单系统的内部流程不写；系统之间的差异用交叉引用表达，不做同篇横比。
5. **只写引擎与系统。** 不写客户端的呈现、交互与实现归属。

### 形式

- 不用围栏代码块；命令、类型、文件名用行内代码。
- 交叉引用固定写作 `→ 参见：[文档标题](相对路径)`，放在段落末或独立行。
- 先给结论，再给支撑它的关系；因果只交代必要的一层，比喻至多一句。

### 何时新建文档

- 出现一个独立的设计概念，其意图与关联无法用现有文档的一两段说清；否则更新已有文档。
- 新建、改名或合并后，立即更新本页索引。
