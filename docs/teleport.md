# 传送

结论：传送是**一次直接跳到一个真名对应的舞台**，不是沿路径走多格。它不改变普通移动：`move` 仍然只能走当前开放邻接边，`teleport` 只判断目标真名能不能解析到舞台。

## 规则

- actor 必须在 `actions` 里拥有 `teleport` 能力；
- 目标写舞台真名，且这个名字必须能解析到本世界的一个舞台；
- 不要求目标在 `stage_visits` 里，也不要求 actor 曾经听说或见过它；
- 源舞台与目标舞台都不能 `teleport_blocked`；
- 目标不能是当前舞台；
- 一次只传送到一个舞台，没有中间舞台、没有沿途观察，也没有“沿开放图找路径”的快速旅行。

`teleport_blocked` 只影响传送，不阻止普通 `move`；舞台是否物理可达与传送资格是两件事。

## 输入判定

传送只做输入判定，不查任何知识账：名字必须能解析到舞台，`#编号` 与舞台 id 都不是名字。

编号只表示「看得见但还没命名的站位」，模型工具与玩家入口共用同一份参数校验；服务端解析也只按名字查，`#序号` 与 id 都解析不到——参数校验可能被绕过，解析器不会。

“知道真名”不是资格：说得出名字就能去，因此模型可以用常见地名试探世界。引擎里没有传送知识表，只有舞台名。

## 访问历史

`stage_visits` 记录 actor × 舞台：

- 建局时记录初始舞台；
- 每次正常移动到达时更新；
- 每次传送到达时更新。

它是舞台认知的唯一账本：名字、地图与候选提示都从这里读，没走过的舞台对 actor 而言只有 `#序号`。它不参与任何通行判定——`move` 的权限在邻接边，`teleport` 只认真名解析。

读取时按 `first_visited_at` 升序；同一回合的多次到达共用同一个时间戳，并列项再按 stage 的 `ordinal` 兜底排序，保证顺序可复现，所以列表里的先后不一定是同一回合内的真实到达先后。

## 候选列表

NPC 回合里的“可传送”列表只列：

> 去过的舞台 ∩ 未被 `teleport_blocked` 的舞台。

它只是一份省事清单，不是可传送集合：候选值不做成 enum，actor 写任何能解析到舞台的真名都成立。去过但被禁传的舞台仍可出现在记忆/地图里，但不进入候选列表。

## 观察与事件

传送是瞬时事实：

- 源舞台的观察者看到“某人在原地消失了”；
- 目标舞台的观察者看到“某人出现在这里”；
- 公共事件记录一次传送；
- 没有中间舞台，也没有沿途状态变化。
