# 术语表：名字与引用

同一个实体在不同观察者眼里可能处于不同的识别状态。这一页只定义命名本身；机制归属各自的系统文档。

## 结论

**名字是知识，引用是地址。** 系统用真名寻址，角色只认得被世界告知过的真名；两者混用会同时破坏路由与认知隔离。

## 术语

| 术语 | 指什么 | 出现在哪里 |
| --- | --- | --- |
| **名字** | 实体的名字，例如 `奥德里克`、`墓园`、`松脂火把`。角色名与场景名在 world 内全局唯一；道具名按持有者 / 场景唯一。名字不含 `@`、`#`、空白与 `.` | 内容、API、日志、数据库、工具参数 |
| **识别**（recognition） | 某个观察者是否认得某具形象。认得即知道真名；不认得只知道编号与外观 | `actor_recognitions` |
| **引用**（reference） | 由观察者视角拼出的地址：`@真名`（你认得他）或 `#12`（你还不认得他）。只能用在系统写给角色的文本与工具参数里，不得说出口 | 工具参数、名单、观察、行动反馈 |
| **形象**（presentation） | 一个 actor 可被看见的那具身体：稳定识别特征加当前外观。换形象即改变可辨识性 | `actor_presentations` |
| **内容键**（content key） | 内容层引用实体的稳定标识，例如 `odric`；避免用展示名当引用 | `Actor.key` |

## 为什么分开

- **名字不是地址**：同一个角色在不同观察者眼里可能是 `@奥德里克` 或 `#12`；寻址用 id，展示用引用。
- **识别没有别名层**：只有认识与不认识两种状态；称号与关系称谓是设定和台词里的说法，不是地址。
- **引用不是名字**：`#12` 只是「你还不知道他是谁」的编号；它不是知识，也不该被记住当成名字。

## 两个面

- **世界面**：agent 看到的一切。名单给引用与已穿戴装备摘要：认得是 `@真名`，不认得是 `#12`；需要外观时另起一行 `#12 外观：…`，**外观不内联进句子**，认得就不再单列外观。stage / world 写入的 environment、世界裁决与结局文案不得含 `@`、`#编号` 或角色名字，写入与内容校验都会拦截；actor 读取时再按观察者脱敏：本场角色写成 `@真名`，不认得就写 `#12` 加独立外观行（**在场者一定看得见对方**），只有无法观测的旧数据才退成「某个不在场者」。
- **控制面**：客户端、CLI、故事整理器看到的完整状态。公共事件流与实体状态只写名字与稳定 id，不写引用标记，客户端自行决定展示与隐藏。

客户端寻址接受稳定 id、名字与引用三种写法，优先用 id。客户端的移动目标用观看者投影里的 `scene.exits[].stageId`；出口的展示名只用于显示。客户端要按角色视角展示时，用观看者投影读取该角色的记忆与引用，而不是重新渲染公共事件流。

## 适用范围

- **角色与场景**：真名全局唯一，可被 `@真名` 引用。角色名是知识（按观察者识别）；场景名是地点标签（公开）。
- **道具**：名字是公共标签，按持有者 / 场景唯一，允许跨作用域同名；只写纯名字，不用 `@`。
- **世界**：没有可被称呼的名字，只存在于控制面（例如「枯钟修道院的故事」）。

## 现状边界

- **形象切换只有数据原语**：`insertPresentation` / `switchCurrentPresentation` 与「识别按形象存」已经就位并有测试，但还没有游戏内的伪装 / 变身入口。
- **名字获取靠扮演层自律**：引擎只拦系统层标记（`@` 与 `#编号`），并校验记名时写的是真名；角色是否「该知道」某个真名，由提示词与对话审核约束，不做硬校验。
