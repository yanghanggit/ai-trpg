# 术语表：名字与引用

同一个实体在不同平面上有不同的叫法。这一页只定义命名本身；机制归属各自的系统文档。

## 结论

**名字是知识，引用是地址。** 系统用名字寻址，角色只知道自己被世界告知过的名字；两者混用会同时破坏路由与认知隔离。

## 术语

| 术语 | 指什么 | 出现在哪里 |
| --- | --- | --- |
| **名字** | 实体的名字，例如 `奥德里克`、`墓园`、`松脂火把`。角色名与场景名在 world 内全局唯一；道具名按持有者 / 场景唯一。名字不含 `@`、`#`、空白与 `.` | 内容、API、日志、数据库、工具参数 |
| **称呼**（known-as） | 某个观察者相信某个角色叫什么。可以是假名、误称、身份代称，也可以改口；不要求等于名字 | `name_knowledge` |
| **引用**（reference） | 由观察者视角拼出的地址：`@名字`（你知道他是谁）或 `#12`（你还不知道他叫什么）。只能用在系统写给角色的文本与工具参数里，不得说出口 | 工具参数、名单、观察、行动反馈 |
| **形象**（presentation） | 一个 actor 可被看见的那具身体：稳定识别特征加当前外观。换形象即改变可辨识性 | `actor_presentations` |
| **内容键**（content key） | 内容层引用实体的稳定标识，例如 `odric`；避免用展示名当引用 | `Actor.key` |

## 为什么分开

- **名字不是地址**：同一个角色在不同观察者眼里可能是 `@奥德里克`、`@守墓人` 或 `#12`；寻址用 id，展示用引用。
- **称呼不是名字**：信念可以错、可以被骗。把称呼写成名字映射，就丢掉了误认与说谎的空间。
- **引用不是名字**：`#12` 只是「你还不知道他是谁」的编号；它不是知识，也不该被记住当成称呼。

## 两个面

- **世界面**：agent 看到的一切。名单只给引用：知道名字是 `@名字`，不知道是 `#12`；需要外观时另起一行 `#12 外观：…`，**外观不内联进句子**，有名字就不再单列外观。stage / world 写入的 environment、世界裁决与结局文案不得含 `@`、`#编号` 或角色名字，写入与内容校验都会拦截；actor 读取时再按观察者脱敏：本场角色写成 `@名字`，不知道名字就写 `#12` 加独立外观行（**在场者一定看得见对方**），只有无法观测的旧数据才退成「某个不在场者」。
- **控制面**：客户端、CLI、故事整理器看到的完整状态。公共事件流与实体状态只写名字与稳定 id，不写引用标记，客户端自行决定展示与隐藏。

客户端寻址接受稳定 id、名字与引用三种写法，优先用 id。客户端的移动目标用观看者投影里的 `scene.exits[].stageId`；出口的展示名只用于显示。客户端要按角色视角展示时，用观看者投影读取该角色的记忆与引用，而不是重新渲染公共事件流。

## 适用范围

- **角色与场景**：名字全局唯一，可被 `@名字` 引用。角色名是知识（按观察者信念）；场景名是地点标签（公开）。
- **道具**：名字是公共标签，按持有者 / 场景唯一，允许跨作用域同名；只写纯名字，不用 `@`。
- **世界**：没有可被称呼的名字，只存在于控制面（例如「枯钟修道院的故事」）。

## 现状边界

- **形象切换只有数据原语**：`insertPresentation` / `switchCurrentPresentation` 与「名字按形象存」已经就位并有测试，但还没有游戏内的伪装 / 变身入口。
- **名字获取靠扮演层自律**：引擎只拦系统层标记（`@` 与 `#编号`）；角色是否「该知道」某个名字，由提示词与对话审核约束，不做硬校验。
