# 管理后台

`apps/admin`：控制面的图形界面。它读的是全知视图（建局数据、轨迹、记忆、探针），和 `apps/web`
的观看者投影是两套读者；把两者并进一个产物会让遮蔽与全知在同一个响应里打架。

## 现在的形状

- 独立 Vite 应用，`apps/*` 工作区自动包含；`pnpm dev` 会一起起，端口见 `.env.example`。
- 只监听 `127.0.0.1`，不随局域网暴露，也不承诺随生产部署——它目前是运维台，不是产品面。
- 身份固定 `admin`（`Authorization: Bearer admin`）。服务端 `src/identity.ts` 有一张写死的运维名单：
  `admin` 越过 owner 检查、能读全库与机器级读数；`demo` 是玩家身份，只能碰自己名下的局。
- 总览只留两层：**身份**（以谁的身份读、owner id）→ **节点**（`GET /status` 给出的
  进程 / 数据库 / 轨迹目录）。内容各自一页：库名点进 `/games`，轨迹目录点进 `/traces`——
  局是那台机器库里的行，轨迹是那台机器的磁盘，入口都挂在节点上。
- `/traces` 是**阅览器**不是报表：一层一屏——`/traces`（局目录，`GET /traces/files` 只给元数据）、
  `/traces/:game`（回合）、`/traces/:game/:turn`（原始事件）。统计口径留给 CLI，页面不做聚合。
- `GET /status` 是节点自述：pid、node、监听地址、库名与 host、轨迹目录与局目录数，
  凭据一律不出现。它描述的是**当前进程**，不做跨进程汇总。
- `/g/:slug/build` 是**建局数据**：world / stage / 通路 / actor / 形态 / 道具 / 玩家归属的原始行
  （`GET /games/{game}/build`），从局列表的「剧本」列进入。运行时状态不在这页——它每天都在长。
- 局控制台只留两样：三层回合推进与空过、只读旁路（记忆 / 真名扫描 / 探针 / 快照 /
  故事 / 压缩）；顶部三个按钮：事件流、刷新、危险操作。作业表与轨迹表从这一页撤掉——
  同一局同时只有一个作业，几秒就过，摊成表没有阅读价值；轨迹有自己的三层阅览器。
- `/g/:slug/messages` 是**事件流**独立一页：整屏一张长表（# / 类型 / 可见性 / 内容 / 时间），
  默认每 5 秒自动重读（`AUTO_REFRESH_INTERVAL_MS`），顶部「自动刷新：开 / 关」可停。
  开关不跨路由记住。入队只回一行「已入队 + 作业 id」，结果去这一页看。
- 危险操作（结束一局 / 删除一局）收进顶部按钮的弹窗：一局只做一次的事，不占主页面版面。
  弹窗本身就是那次确认，按下去就执行。
- 写操作仍然是「确认 + 服务端说了算」：入队成功不算回合发生过，落没落地只看事件流与轨迹。

## 页头与导航规则

一屏顶部的三样东西各管一件事，别混着写：

1. **面包屑 = 容器路径**：从「总览」起逐级可点，只写页面名（总览 / 局 / 轨迹）。
   当前页不占一级；这一页对象（slug、回合 id）也不在面包屑里重复出现。
   对象作为别页的父级时照写（`/traces/:game/:turn` 的 `clock-e2e` 可点回回合页）。
   根页（`/`）没有上级，就没有面包屑。
2. **h1 = 这一页的对象**：slug、回合 id（截 8 位）用 `<code>`；列表页的对象就是那一类东西，
   h1 直接写页名（总览 / 局 / 轨迹），不带标签。
3. **页名 = h1 右侧的 `.page-kind` 标签**：局控制台 / 建局数据 / 事件流 / 回合 / 事件。
   同一对象下的多个页只靠这个标签区分——这样 `clock-e2e` 在页头只出现一次。
4. **右上角只放动作**：按钮与「进行中」徽标。读数（共 N 局 / 共 N 条 / 文件数 /
   目录路径 / 回合类型·对象·时间）一律落在面板标题下方，一行 `.muted`。
5. **局控制台是这一局的枢纽**：控制台右上角通往 `建局数据` 与 `事件流`，
   两个子页右上角都留一个 `局控制台` 回来。

## 已知缺口

- **名单还不是角色**：`admin` / `demo` 只是两行用户 + 一张写死的名单，`users` 表没有 `role` 列。
  真角色体系要等会话令牌落地。
- **只有一个节点**：后台连的是 `VITE_API_BASE_URL`（缺省同机 `DEFAULT_SERVER_PORT`）那一个服务端进程。
  「多进程 / 多节点」要先有第二个服务端，且每个进程得能自报身份；现在先按单节点做，
  结构上留了「节点」这一层。
- **轨迹仍跨全部局**：`/traces` 已只对运维开放（`requireAdmin`），但它仍然把整台机器的回合
  混在一起，没有按局隔离——这是调试口径的本意，别拿它当「某局的历史」。
- **仍然不是登录**：`Bearer admin` 谁都能发。后台能「只给运维用」靠的是客户端写死身份 +
  服务端名单决定阅读范围 + 只监听本机，不是访问控制。
- **取消作业没有入口**：作业表撤掉后，正在跑的作业无法从界面上取消（接口与 CLI 还在）。
  真要停一个卡住的回合，仍可以走 CLI；等跨局作业总览做出来再补。
- **没有守卫**：`scripts/check-client-scope.mjs` 只守住「web 不读控制面」。反方向的
  「admin 不读 `ActorView`」没有必要——后台看玩家视角是为了对照，不是缺陷。
