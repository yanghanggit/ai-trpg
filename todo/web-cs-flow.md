# 客户端回路：还差什么

目标是把「一个回合从界面发出去、到看得见结果」这条回路做顺。现在的实现见 `apps/web/src/features/turns/` 与 `apps/web/src/pages/game/TurnDialog.tsx`。

## 1. 停止（对应 CLI 的 `job-cancel`）

服务端早就支持：排队中的当场撤、执行中的在落账前的检查点停下（模型调用会被真正中断）。web 没有入口。

- 验收：点「停止」后，排队中的作业立刻变 `canceled`；执行中的先显示「正在停」，一秒内变 `canceled`；已经进写事务的那一回合会跑完并以 `succeeded` 收尾（此时「停止」不生效，界面要按终态说话，别宣布已取消）。
- 位置待定：动作浮窗内（挨着进度）还是顶部提示条上。倾向浮窗内 + 顶部提示条一个小按钮。
- 涉及：`features/turns/api.ts` 加 `cancelTurnJob`，浮窗加按钮，终态复用 `useTurnJob`。

## 2. 订阅入口（`useJobStream` 已写、未接）

`apps/web/src/features/turns/useJobStream.ts` 实现了 SSE 读法（按作业收、按更新时间去重、断线交给 `EventSource`），但没有任何页面用它。现在页面是 2s 轮询 + 终态失效重读。

- 接进浮窗后：推送在、轮询作为兜底；两者读的是同一行、同一形状，界面不分叉。
- 需要顺手定的一件事：断线重连后界面怎么对齐。服务端会按游标自动补发，客户端只需要「收到就覆盖更新的那一版」，这一点 hook 已经做了。
- 不接的代价：现在也没问题，只是 SSE 基建没有被真实客户端用过。

## 3. 作业历史视图（对应 `jobs --status all`）

排查用：一局的所有作业、状态、错误码、进度。CLI 有，web 没有。

- 位置待定：翻成「排查」浮窗，或只放 mock 目录之外的 dev dock。
- 验收：能看见失败作业的 `errorCode` 与错误文本，能看见已取消的那条。

## 4. 真机走查清单

用 `pnpm dev` 起服务端 + 页面，逐条走，记录卡手的地方：

1. 建局 → 进局页 → 「动作」→ 没有顺位时先「开一条顺位」。
2. 「接管」→ 顺位里自己变成 `玩家`。
3. 说一句 → 观察：进度文字、「记录」里有没有这句、顺位计数 +1、关窗后主页投影有没有变。
4. 回合进行中再点一次提交 → 应显示「这一局已有回合在跑」而不是发第二个。
5. 「这一趟我空过」→ 计数 +1，且不卡队首。
6. 「推进一步」数次 → agent 回合 → 它的舞台回合 → 本轮人人动过后 world。
7. 回合进行中刷新页面 → 顶部提示出现，浮窗能接上同一条作业。
8. 换多舞台种子再走一遍，重点看「移动之后，舞台回合推到的是哪个舞台」。

观察点（走查时由服务端这边核对，不用界面看）：`jobs` 表的 `status/progress/errorCode`、`action_orders` 的 `turnsTaken`、`logs/trace/` 里的回合轨迹与 dispatch 对账。

## 5. 已知的小瑕疵

- 页面开着时 `useActiveTurnJobs` 每 2s 查一次，没有安静期。
- `runTurnAndWait` 的 120s 超时是客户端自定的；超时后作业可能仍在跑，界面会先说「失败」，重开浮窗能接上。
- 浮窗的「接上正在跑的作业」只接第一条（同局本该只有一条，由串行键保证）。

## 刻意没做

- 动作种类停在 4 种（说/看/走/等）。要补时是「种类 → 字段」的表，不是逐个手写表单；其余 18 种见 `apps/server/src/game-ops/player-action.ts` 的可判别联合。
- 「一键走完一轮」：现在一次只推一个 actor。做之前先走查，看手动节奏到底够不够。
