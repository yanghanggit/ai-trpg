# 已定的取舍

这些是**决定**，不是待办。想改之前先看理由，别在实现里顺手改掉。

## 寻址

- 调度命令里的角色一律用**真名或编号**（`#n`）。服务端的玩家入口**不接受**「他认得的名字」：那是扮演信息、属于「认不认识」这一层记忆机制，不是命令寻址。
- 客户端会做一件事：把界面上认得的名字换成它背后的签名编号；换不出来就不让选，绝不把昵称发上去让服务端猜。
- 相关：`docs/web-client.md`、`apps/server/src/game/actor-state/locate.ts`、`apps/web/src/features/turns/targets.ts`。

## 回合与作业

- 一个回合一个动作。玩家入口没有「一份计划里连做几件事」的形状，连打这个入口就是几个回合。
- 回合作业 `max_attempts = 1`：落账不幂等，整回合不自动重试，重试归客户端。
- 串行键是**局级**（`turn:<gameId>`）：同一局同一时刻只有一个回合在跑，后来的入队直接拒（409），不排队。
- 视图过期在**执行开始时**比对，且有自己的错误码（`stale_view`）：客户端重读重算，不解析错误文本。
- 取消只覆盖到落账开始之前；之后忽略请求、作业照常成功。
- 进度只放「这一步在做什么」+ 一句轮次补充，不放世界状态。作业行不能成为第二份世界。
- 推送只发作业行，不发世界状态；事件是快照不是流水账，可能合并。
- 作业行**永久保留**（暂时）；清孤儿用手动脚本，不做自动归档。

## 客户端

- 页面只吃数据、容器取数；浮窗里要取数的部分由外层注入（`renderHistory` / `renderTurn`），mock 传假实现。页面因此不连服务端，mock 也不需要拦网络。
- 客户端是编排者：谁先谁后、什么时候推舞台与世界，由客户端算；服务器只保证同局互斥。改这条等于改产品形态。
- 客户端不另立判断口径：回合算不算数、要不要补空回合、取消生效没有，都读契约里已有的那几样。
- 能力对照：CLI 能做的 web 必须能做。只缺界面是 web 的欠账，连接口都没有是服务端缺口——不拿「界面上用不到」当理由。

## 契约与数据

- 数据库只有一份基线迁移，开发期不留迁移历史（改 schema 的步骤见 [服务器遗留](server-debt.md)）。
- 契约由 openapi 生成（`packages/api-client`），生成物 gitignore；契约改动后 `pnpm gen:api`。
- 错误码是稳定的 snake_case 枚举；新增码要同时更新 `apps/server/src/plugins/error-handler.ts` 的状态映射与相关文档。
